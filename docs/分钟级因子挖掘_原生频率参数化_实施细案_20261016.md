# 分钟级因子挖掘 · 原生频率参数化 · 实施细案

> 日期：2026-10-16 ｜ 状态：实施中 ｜ 关联：P1.5 分钟数据面移植（commit 443900da）

## 1. 背景与根因（为什么上一轮 1min 挖掘 56 分钟零产出）

2026-10-16 14:59 启动的 1min 挖掘任务 `7432918e08a14141`，进度钉死在 19%（=Loop_0 coding 阶段
的数学上限，非卡死），56 分钟后被终止，`factors: []`。日志实证 38 次 Final Decision 全 FAIL、
「not daily」×92、「输出频率」×71。根因是**两个互斥的裁判**在互搏：

| 面 | P1.5 移植后的状态 | 后果 |
|---|---|---|
| 数据面 | ✅ 已分钟化（day+1min 混合 provider） | 生成的数据帧是分钟索引 |
| 提示词面 | ✅ `_minute_prompt_block` 要求「输出 1 分钟粒度」 | 批评家 LLM 要求分钟输出 |
| 评估器面 | ❌ fork `FactorDatetimeDailyEvaluator` 硬编码「出现 1min 间隔 = 非日频 = 一定错了」 | 分钟输出必被价值闸 FAIL |
| 口径面 | ❌ `render_eval_criteria_block` 全是日频话术（每日截面/日频 IC） | LLM 反复被拉回日频 |
| 物化面 | ❌ `rd_mined_materialize` 零频率感知（日频共享缓存、日频折叠靠 `keep="last"` 的巧合） | 就算挖出来也物化不对 |

LLM 在「输出分钟→被评估器判错」「输出日频→被批评家判错」之间振荡，evo 轮耗尽 → `CoderError`
→ fork `skip_loop_error`（`rdagent/app/qlib_rd_loop/factor.py:18-19`）静默跳轮，任务烧完
Loop_0/1/2 后以空因子收场。**结论：P1.5 只通了数据面，裁判席没有换人。**

## 2. 目标与不变量

- **目标**：挖掘链全链**频率参数化**——`day`（现网行为逐字节不变）与 `1min`（原生分钟）同一条
  代码路径，靠任务级频率开关分派；后期 `5min`/tick 级挖掘只需增一条 `FreqSpec` + provider 支持。
- **不变量 A（日频零回归）**：`QM_MINING_BAR_SECONDS` 缺省/为 0 时，fork 评估器、提示词、物化
  全部与今天逐字一致。
- **不变量 B（月频值口径不变）**：分钟挖掘的因子**物化成日频列**（每交易日最后一根有效 bar 的
  值），值级查重、门禁、落库、目录注册、训练消费全部走既有日频通道，不改任何下游契约。
- **不变量 C（诚实失败）**：分钟任务的任何一环拿不到分钟数据面/产出日频输出时**响亮失败**，
  绝不静默降级用日频数据顶替（那会造出一列"看着成功、值全错"的因子）。

## 4. 频率契约（单源）

`backend/services/engine/alpha_agent/mining_config.py` 新增：

```python
ENV_BAR_SECONDS = "QM_MINING_BAR_SECONDS"

@dataclass(frozen=True)
class FreqSpec:
    freq: str                    # "day" | "1min"
    bar_seconds: int             # 0 = 日频；60 = 1min
    label: str                   # 展示名（前端/提示词）
    value_collapse: str | None   # 物化折叠规则；日频=None（天然日频）

FREQ_SPECS: dict[str, FreqSpec] = {
    FREQ_DAY:    FreqSpec(FREQ_DAY, 0, "日频", None),
    FREQ_MINUTE: FreqSpec(FREQ_MINUTE, 60, "分钟级", "last"),
}
```

- `task_env(...)` 在写 `QM_MINING_FREQ` 的同时写 `QM_MINING_BAR_SECONDS`（数值单源）。
- **fork 只认数值**（`QM_MINING_BAR_SECONDS`），不认频率词汇表——词表只活在 backend，
  新增频率不需要动 fork。
- 命名口径：因子列名不携带频率（值即日频折叠值）；频率只进 provenance（metadata/清单）。

## 6. 折叠口径（为什么是「最后一根有效 bar」）

- 语义 = **收盘时点快照**：日内因子的日频投影取收盘前最后观测值，与"当日收盘时的因子状态"
  一致，产业链惯例（收盘后调仓/训练数据构建）。
- 「有效」= 先剔 NaN/±inf 再取 last：某股尾盘 bar 缺值（停牌前最后一根）时退到该日最后有效
  值，而不是整日丢弃。
- 显式排序后取 last（不依赖输入行序）——旧实现 `duplicated(keep="last")` 的"折叠"是巧合，
  产出依赖因子代码的输出顺序，属静默依赖，本次收编为契约。
- 规则入 provenance（`value_collapse: "last"`），将来若要 mean/first 只改 `FreqSpec`。

## 7. 验收探针

1. **fork 单测**（容器内真 import）：日频模式分钟输出 FAIL（文案不变）；分钟模式分钟输出 PASS、
   日频输出 FAIL；`QM_MINING_BAR_SECONDS` 缺省行为 = 上游逐字。
2. **折叠金样**：构造含午餐断档/竞价 bar/inf/末日 NaN/乱序输入的分钟帧 → 断定日频折叠 =
   每股每日最后一根有效值（host 可直接跑）。
3. **日频零回归**：既有日频任务因子重跑物化 dry-run → 清单/库值不变；全量 unit 回归零新增失败。
4. **端到端真机**：loop_n=1 的 1min 挖掘任务全链跑通——
   Loop_0 coding **PASS**（此前 38 连 FAIL 的对照）→ 因子落库 `native_freq=1min` →
   自动物化 → `rd_mined` dt=* 分区出现新列（值抽样人工核对量级）→ 清单含 provenance 三键。
5. **回归对照**：同一验收脚本对一条存量日频任务因子跑物化 dry-run，产出与改动前一致。

## 8. 风险与边界

- **fork 补丁同步**：容器 `site-packages` 是拷贝安装，patch 必须 docker cp + 清 pyc +
  注册 `FORK_DIVERGENCE.md`；镜像重建靠 repo 源文件（本补丁在 repo 里，天然后续）。
- **分钟 provider 覆盖**：约 121 交易日、csi300；窗口超覆盖在 mining 侧已拦，物化面按
  因子 metadata 窗口定位 face，窗口 = 挖掘窗口（挖什么折什么）。
- **执行耗时**：分钟 face 8.6M 行，因子代码在 pandas 上滚动窗口的耗时上探 2~5 分钟/因子，
  超时提到 1800s 且日志可见；物化面板长任务属预期。
- **IC 口径**：分钟任务的 in-loop qrun IC = 1min 前向收益（P1.5 conf 已设），与提示词口径
  同源；物化后的值级评估仍走日频通道（不变量 B）。
