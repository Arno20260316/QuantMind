# 期货数据面扩容 · 国内数据集二批 — 侦查与实施细案（2026-10-15）

> 缘起：用户点名「期货市场还能增加哪些内容？国内有数据的、写到期货市场数据里面去，免费的就可以」。
> 本细案 = 全量接口侦查收据（akshare 1.18.88，容器内实测）+ 二批数据集定义 + 接线与回填计划。

## 一、侦查收据（2026-10-15 实跑，全部为真实调用）

### 可用（本批纳入）

| 接口 | 内容 | 实测收据 | 频率 |
|------|------|---------|------|
| `futures_spot_price_daily(start,end,vars_list)` | 生意社现货价+基差（近月/主力双口径+基差率） | 全品种单日 52 行（0.2s）；历史可回填至 2022-01（实测） | 日频 |
| `futures_settle_shfe/czce/ine(date)` | 日结算参数（结算价/保证金率/手续费/平今费/涨跌停/限仓） | SHFE 301 / CZCE 243 / INE 63 行；2024-10 可回填 | 日频 |
| `futures_rule(date)` | 品种级交易规则（保证金比例/涨跌停幅/合约乘数/最小变动价位/限价单手数/特殊合约调整） | 162 行（全所）；2024-10 可回填 | 日频 |
| `futures_contract_info_{shfe,czce,cffex,ine}(date)` | 合约生命周期（上市/到期/开始·最后交割日/挂牌基准价） | 301/243/710/63 行 | 日频快照 |
| `get_futures_daily(start,end,market)` | 交易所官方日行情全合约（含**真实成交额 turnover**、结算价、持仓量） | SHFE/CZCE/CFFEX/INE 可用（305/243/28/67 行）；深度 ≥ 2023-06 实测 | 日频 |
| `futures_inventory_em(symbol)` | 东财交易所库存（68 品种，接受代码/中文名） | 每品种 67 行（滚动 ~3 个月，2026-07-07 起） | 日频滚动 |
| `futures_index_ccidx(symbol)` | 中证商品期货指数 / 价格指数 | 969 行（2022-10 起，含结算点位/年化收益） | 日频 |
| `futures_fees_info()` | 全合约费率表（乘数/最小跳动/开平今费率[元/手]/保证金率） | 870 行快照 | 低频快照 |
| `futures_hog_{core,cost,supply}(symbol)` | 生猪产业链（外三元/内三元/土杂猪/玉米/豆粕/仔猪/母猪/猪肉批发价/猪粮比价等 15 序列） | 各 ~90-370 行全量返回 | 日频快照 |
| `futures_hold_pos_sina(symbol,contract,date)` | 新浪席位排名（**补 SHFE/CZCE 会员持仓缺口**） | SHFE（rb/cu/ag 20 行）+ CZCE（AP2610/SR2701 有效，**须 4 位年**）；DCE/CFFEX/INE 无覆盖 | 日频 |

关键格式陷阱（写解析器必读）：
- 生意社 `date` 为 `YYYYMMDD` 字符串；非交易日会 warning 但正常跳过。
- CZCE 结算参数为带千分位字符串（`'8,000.00'`）、涨跌停 `'±8'`、保证金 `'20'`（百分数）——必须清洗。
- 新浪席位 CZCE 合约需 `AP2610` 格式（交易所官方口径是 `AP610`，3 位年）。
- `get_futures_daily` 的 SHFE 源多一列 `index`（丢弃）；DCE 死、GFEX 恒空。

## 三、依赖与顺序

- `member_rank_sina` 依赖 `spot_basis` 的 `dominant_contract`（当日主力合约来源）；
  同日链路里 spot_basis 先跑（`_run_extra_tasks` 按 datasets 顺序执行）。
- `exchange_daily` 与 `contracts_daily` 并存不合并：来源层不同（官方 vs 新浪），官方表提供真实 turnover。
- 生意社 date 维度幂等：分区覆盖写。

## 五、验收标准

1. 新 pytest（零 mock 直连产物）：分区存在/行数下限/关键列齐备/健康带
   （settle_price>0、保证金率∈(0,1]、基差率 |x|<50%、库存≥0、规则乘数∈合理集）。
2. 归一化单测：CZCE 千分位/± 号清洗、新浪 CZCE 合约码 4 位年转换。
3. 实跑回填后：随机抽 3 日核对 生意社基差 vs 盘面（RB 主力基差符号方向正确）、
   settle_params 保证金率与 futures_rule 品种保证金对得上（抽样）。
4. 目录注册后：`GET /api/v1/admin/data-platform/quantfutures/catalog` 含 10 个新数据集且 stats 非空。
5. 既有 30 项期货市场分析 pytest 不回归。

### 实施中发现的坑（均已处置并有回归测试）

1. **ccidx 孪生列**：源帧「涨跌/涨跌幅」与 `dailyIncreaseAndDecrease*` 成对出现，
   若都映射到 `change`/`pct_change` 会产生重名列 → `df[c]` 退化为 DataFrame → `to_numeric`
   炸 `arg must be a list...`。处置：只保留中文列映射 + `df.loc[:, ~df.columns.duplicated()]`
   兜底 + `test_ccidx_rename_targets_are_unique`。
2. **hog_chain 三种 schema**：供应品种存在「周期+多指标宽表 / 日期+本周 / 日期+值」三形态；
   另有 pandas 2+ 首元素格式推断陷阱（首元素 `"2012"` 把整列格式锁死为 `%Y`，
   后续 `"2026-05-28"` 静默变 NaT）。处置：`_norm_hog_frame` 三分支 +
   `_parse_hog_time` 按格式掩码逐类解析。
3. **contract_meta 混合类型**：跨所 concat 后日期列混有 `datetime.date` 与字符串
   （CZCE 带「北京时间」后缀），parquet 报 `Conversion failed for column listed_date`。
   处置：concat 后对 6 个日期列 `_date_str`、8 个数值列 `_clean_num` 强转。
4. **`_write_part` 残骸目录**：parquet 写失败时 `mkdir` 已执行的 `dt=` 空目录残留，
   会被测试的「最新分区」误判。处置：写失败且无 `data.parquet` 时 `rmdir` 清理；
   测试 `_latest_partition` 只认真正带 `data.parquet` 的分区。
5. **exchange_daily 休市日误伤熔断**（回填实测事故）：四所接口对休市日返回**空帧不抛异常**，
   旧逻辑「空帧也算连续失败 ≥3 次即禁用」在 2026 春节连休处把四个市场全部振出局——
   2026-02-16 起整段被跳过（重跑时补写 154 个交易日分区；该段另有 17 个节假日空帧属正常）。
   处置：抽 `_VenueBreaker` 熔断器——空帧=无数据（清连败计数），只有异常才计连败；
   连败 ≥5 次进 20 天冷却后自动重探（限流多为瞬时，不再一票否决整个回填）。
   4 项单测覆盖（休市不清败/熔断冷却/重探/成功复位），随后整段重跑回填——
   终态 written 222 / `disabled: []`，逐日核对零真缺口（见文末「回填终态」）。

### 偏差与源侧问题（登记）

- **sge_settle 实施中撤项（定性错误 + 通道被拒）**：二次核实 `futures_settlement_price_sgx`
  实为**新加坡交易所（SGX）**衍生品历史结算价（接口 docstring 与数据源 URL
  links.sgx.com/FUTURE.zip 均可证），细案原意向的「上金所 SGE 结算」在 akshare 中并无
  对应源（sge 家族函数全是现货，且现货已被一批 `sge_daily` 覆盖）；且该接口的
  日期→num 换算依赖 `push2his.eastmoney.com`，容器出口被拒（Empty reply）——整项从
  交付中撤除（注册表/目录/测试/细案全清），实现可于 git 历史找回。遗留登记见 §六。
- **spot_basis 源侧噪声**：SH 烧碱 `dom_basis_rate` 实测 1.77（生意社现货口径与盘面脱钩），
  属上游数据问题；健康测试阈值定 95% 而非 99%，注释说明。
- **inventory_em 字典 80 键 68 有效**：股指/国债等品种东财无库存数据（正常空），
  健康断言按 ≥50 个品种文件。
- **member_rank_sina 依赖 spot_basis 产物**：读取最新 `dt=` 分区的 `dominant_contract`，
  故回填顺序中排在 spot_basis 之后；且默认不进 `DEFAULT_EXTRA_DATASETS`（请求量大）。
