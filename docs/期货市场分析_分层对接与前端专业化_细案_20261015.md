# 期货市场分析（QuantFutures Market Analysis）分层对接与前端专业化规划

> 细案 · 2026-10-15 · 目标：为期货（FUTURES）建立与 A股/港股/美股平级的独立市场分析模块，
> 架构照抄「独立市场目录 + 共享层」模式，**内容按期货机构研究视角重新设计**（不是股票面板换数据源）。
> 同时整理「期货市场研究前端专业化」的机构级分阶段规划。
> 只依赖本地 QuantFutures parquet，无外部实时依赖（实时快照走 futures_realtime 落盘）。

## 一、结论先行

1. **架构照抄 HK/US**：后端 `backend/services/api/market_analysis_futures/`（独立包，feed 按域拆包）+
   复用 `market_analysis_shared/`（零改动）；前端 `electron/src/features/market-analysis-futures/`。
   接线共 4 处：后端 `api/main.py` 两行、前端 `App.tsx` 两行。
2. **内容不照抄**：期货没有「行业资金流 / 估值 / 财报 / 分析师 / 南向 / AH」对应物。期货机构研究
   真正看的是：**期限结构（contango/backwardation）**、**持仓量与沉淀资金**、**仓单库存**、
   **内外盘价差与基差**、**CFTC 持仓**、**品种板块轮动**。这六块构成本模块的差异点。
3. **三个数据链路必须先修（P0）**，否则「持仓分析」做出来是废面板：
   - `daily_forward` 的**持仓量与动态结算价在落盘时被裁剪丢弃**（根因已定位到代码行，见 §4.1）；
   - `contracts_daily`（期限结构唯一数据源）**停在 2026-08-28 且只覆盖 22/82 品种**（§4.2）；
   - `warehouse_receipts` **上游 SHFE 接口失效**（只余 CZCE），页面必须如实标注（§4.3）。
4. **前端基础设施已就绪**：`AppMarket` 枚举、`marketConfig`（FUTURES 条目）、`MarketSelector`（期货按钮）、
   `marketInfer`（期货代码识别）、数据管理 QuantFutures Tab 均已存在；缺的只是「市场分析」这一栏本身。
5. **期货前端专业化不止市场分析一栏**（§六全景规划）：品种终端、首页六宫格、K 线换月标记、
   期货复盘/QQ 推送、资讯流、期货交易日历，按 P1/P2 排序推进。

## 三、模块内容设计（期货机构研究看什么）

### 3.1 设计原则

1. **期货研究三轴 = 价格 × 持仓 × 库存**：股票看「谁在买」，期货看「仓位往哪边加、货往哪边流」。
2. **期限结构是期货独有的 α 源**：近月升贴水（contango/backwardation）与展期收益率，股票市场分析无对应物。
3. **量仓数据只对国内品种成立**（国际实测恒 0、上金所无），页面按品种组诚实标注覆盖。
4. **价格口径 = 主力连续**（新浪 `{STEM}0`），**换月跳空是数据形态不是行情**，页面/终端须披露换月点。

### 3.2 Tab 规划（6 个，每个 Tab ↔ 一个后端 feed 域，1:1 便于维护）

| # | Tab | 核心内容 | 数据来源 | 优先级 |
|---|---|---|---|---|
| 1 | **行情总览** | 全市场统计卡（涨跌品种数/涨停跌停/总成交额/总持仓额）、涨跌榜、成交额榜、持仓额榜（按板块筛选） | `daily_forward` + 乘数表 | P1 |
| 2 | **板块热力** | 116 品种热力矩形（面积=持仓额，颜色=涨跌幅），按 8 大板块分组；板块聚合统计（涨跌幅中位数/资金流向） | `daily_forward` + 品种板块映射 | P1 |
| 3 | **期限结构** | 单品种近远月曲线（15 合约）、contango/backwardation 全景榜、展期收益率榜、主力-次主力价差 | `contracts_daily` | P1 |
| 4 | **持仓分析** | CFTC 国际持仓净仓位榜（黄金/原油/铜/白银…，周度）；国内**持仓量增减仓榜**（增仓上涨=多头趋势、增仓下跌=空头趋势四象限）；沉淀资金变化 | `cftc` + `daily_forward`(position 列) | P1 |
| 5 | **仓单库存** | 分品种仓单总量与日变化榜、单品种仓单趋势曲线；**页面标注数据截至日与覆盖所**（当前仅 CZCE） | `warehouse_receipts` | P2 |
| 6 | **内外盘基差** | 沪金 AU0 vs COMEX GC / 沪银 vs SI / 沪铜 CU0 vs HG（汇率换算后）内外盘溢价率；上金所现货 vs 沪金主力基差（贵金属期现） | `daily_forward` + `fx_daily` | P2 |

### 3.3 功能 × 数据源矩阵（含诚实空白的披露方式）

| 功能 | 数据 | 覆盖 | 口径/披露 |
|---|---|---|---|
| 涨跌/成交/持仓榜 | daily_forward（CN 80 品种完整量仓） | 国内 ✅ / 国际仅价格 | 国际品种量仓列显示 `—`，不落 0 |
| 沉淀资金（持仓额） | position × close × 乘数 | 仅国内 | 页面注明「名义持仓额口径」 |
| 期限结构 | contracts_daily | 22→82 品种（补跑后） | 披露快照日期 |
| CFTC | cftc 宽表 | 黄金/白银/铜/原油/农产品等 ~15 类 | 周度，标注报告日 |
| 仓单 | warehouse_receipts | CZCE（SHFE/DCE/GFEX 失效） | 大幅横幅标注覆盖所 |
| 内外盘价差 | AU0/AG0/CU0/SC0 vs GC/SI/HG/CL + USD 汇率 | 4 组 | 汇率用中行 mid |
| 贵金属基差 | SGE 现货 vs 沪金/沪银主力 | 贵金属 | 现货无夜盘，口径注明 |
| 会员持仓席位 | — | ❌ 数据未落盘 | **不做**（P1 补采后开） |

### 3.4 明确不做（数据/口径限制）

| 项 | 原因 |
|---|---|
| 期货综合指数 | 新浪主力连续无官方指数；等权合成是自造指数，无对照基准 → 首版不做 |
| 国际品种持仓/沉淀资金 | `futures_foreign_hist` 的 volume/position/settlement 实测恒 0 |
| 成交量加权资金流（股票式） | 期货无「主力资金」概念；期货资金面 = 持仓额变化（本模块口径） |
| 涨跌停统计（严格口径） | 各品种涨跌停板比例不同且随行情调整，首版只做涨跌幅分布，不做「涨停家数」 |
| 会员持仓多空榜 | `member_positions` 从未落盘（§6.4 P1） |
| 期权/波动率曲面 | 无数据源 |

## 四、数据链路先修（P0，模块依赖）

### 4.1 daily_forward 恢复持仓量 + 动态结算价（根因已定位）

**根因**：`backend/scripts/akshare_futures_sync.py::_normalise_daily`（约 L186-215）——akshare 中文列经
`_COL_MAP` 映射后 `df[KLINE_COLS]` **只保留 10 列**，`position`（持仓量）与 `settlement`（动态结算价）
被裁掉。实测对照（A0.CN 2026-10-14）：

| 源（futures_main_sina） | 落盘 daily_forward |
|---|---|
| 成交量=284072、**持仓量=303014**、**动态结算价=5496** | volume=284072，**持仓量/结算价缺失** |

**修复方案**：
1. `_COL_MAP` 增加 `"动态结算价": "settlement"`；`KLINE_COLS` 增列 `position`/`settlement`（缺列源填 None，
   旧分区读取以 `union_by_name` 兼容）；
2. 新建回填脚本 `backend/scripts/quantfutures_backfill_position.py`：拉取 CN_MAIN 82 品种全历史
   （futures_main_sina 一次调用全量返回），与 7771 个已有分区按 `(symbol, time)` join，**只补 position/
   settlement 两列、绝不覆盖既有价格列**（避免新浪主力连续历史视角重写，保护 l1_factors 一致性）；
   幂等可重跑，输出覆盖率统计；
3. 国际品种（GC 等）源列 position 恒 0 → 回填写 NULL 而不是 0（诚实空缺）；
4. 影响面核对：`quantfutures_hub` / qlib builder / l1 构建均为显式列选择，**增列向后兼容**。

### 4.2 contracts_daily 补跑（期限结构唯一数据源）

**现状**：286 文件 / 22 品种 / 数据停 2026-08-28（重量级任务，仅面板勾选才跑）。
**根因**：`task_contracts_daily` 循环 82 品种 × 16 个月份合约 ≈ 1300 次请求，历次只跑了子集。
**好消息**：当前代码 `_norm_contract_kline` **已保留 `open_interest`（持仓量）与 `settlement`（结算价）**
——旧 286 文件是旧版代码跑的缺列数据；**重跑即得带持仓量的分合约数据**。
**动作**：补跑全量（预估 15-25 分钟，后台执行），验收：82 品种覆盖 + 数据日期到 T-1 + 两列存在。
**常态化建议**（P1）：纳入 quantfutures_daily_sync 的可选 daily 档（月度切片增量），不再依赖手工勾选。

### 4.3 warehouse_receipts 数据面标注 + 上游修复规划

- 现状：96 分区，最新 dt=**20260910**，且最新日期只有 **CZCE**（1429 行/27 品种），SHFE 接口失效。
- 本次：**页面如实标注**「数据截至 X · 当前覆盖：郑商所；上期所接口失效待修」+ 覆盖所徽章。

每个域模块 150-300 行、纯函数可单测；`base.py` 是唯一与 parquet 目录耦合的地方。

### 5.2 数据访问与性能约束（必须遵守）

1. **按日期取数一律走显式分区文件列表**（`dt=YYYYMMDD/data.parquet`），
   **禁止对 `daily_forward/dt=*` 全 glob**——文件内自带 `dt` 列会遮蔽 hive 分区列，
   全 glob 逐分区全扫（US 实测 32 倍差距；本仓 7771 分区更甚）。
2. **长窗口（60 日）** 按分区文件列表拼接后一次读入 + `cached` 进程内 TTL 缓存。
3. **contracts_daily / cftc / fx_daily** 小文件全量读入 + lru_cache（286+2+14 文件）。
4. **NaN 安全**：所有数值经 `display.safe_float/pct` 出口；前端 `null` 一律显示 `—`（历史白屏事故防线）。
5. **单位口径**（页面必须标注）：国内期货价格=元（按品种单位：元/吨、元/克…）；成交额 amount=close×volume
   是**估算值**（源无真实成交额），页面标注「估算」；持仓额=position×close×multiplier=**名义持仓额**。

### 交付后截图复核抓出的两个口径缺陷（已修复并锁测试）

1. **铜假价差 −99.00%**：`HG.FUT` 源侧（新浪）按**美分/磅**落盘（close≈661），

   `|spread_pct| < 50`（此类失真的通用闸）。
2. **白银「价差」+18.52% 实为税制差**：沪银盘面含 13% 增值税（投资金免税只覆盖
