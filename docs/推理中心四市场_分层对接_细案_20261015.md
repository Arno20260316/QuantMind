# 推理中心四市场分层对接 细案（A股 / 港股 / 美股 / 期货）

> 2026-10-15 · 状态：实施中 · 前置文档：`docs/推理中心三市场_设计方案.md`（共享壳 + 适配器模式的来源）
> 需求原话：「推理中心也做一个区别A股、港股、美股、期货的分层显示」「最终就是维护也好维护方式来做！分层就像市场分析那样、不同市场做区别。」

## 一、结论先行

1. **机制不动，只加第四个适配器**。推理中心的「一个市场一个包」分层（共享壳 `inference-center-shared` + 每市场 ~50 行适配器 + `App.tsx` 分发器按 Redux `currentMarket` 选页）与市场分析模块同构，是全仓最可维护的分层范式。本次全部工作 = 新建 `InferenceCenterFuturesPage.tsx`（第四个适配器）+ 让整条后端链路对 FUTURES 说真话。
2. **今天存在一个真实缺陷**：`App.tsx:69-75` 的 `InferenceCenterByMarket` 只分了 HK/US 两支，**期货（和 CRYPTO）落入 A 股页兜底** —— 期货用户看到的推理中心套着 A 股联想表、SSE 日历、`normalizeStockCode` 前缀规则，是「看起来能用的错页」。这与三市场方案修过的「美股落 CN 页」完全同型。
3. **期货是「数据面跑通、决策链路未接」的半成品**（三路侦查实测一致）：
   - **已通**：QuantFutures 因子库 `l1_factors` 7770 分区 / 191 列（最新完整日 20261014 共 116 行）；同步调度 `sync_schedule:FUTURES` enabled 03:00 含 qlib 重建，今日已跑；训练/推理白名单、`qm_market_of` 市场归一、`model_features_futures.parquet`、模型市场隔离全在册。
   - **全空**：`qm_user_models` FUTURES=0、`qm_model_inference_runs`=0、`engine_signal_scores`=0 行 —— **一个期货模型都没有**。
   - **缺口**：交易日历无 CME/FUTURES 键（`get_market('FUTURES')` 直接抛 → 静默降级成「只看周末」）；`/research/kline` 无期货分支；`/market/kline` 无 FUTURES 分支（aggregator 没有期货适配器）；`research_service.py` 两处上下文市场白名单漏 FUTURES；`predict-stock` 的符号归一落到 `to_prefix` 会把 `RB0.CN` 改坏；`stock_daily_latest_futures` 表被引用但**不存在**（predict-stock 必 500）。
4. **本轮交付边界**：四市场分层显示 + 上述五处链路修复 + 空模型诚实空态 + 验证与回归。**「训练首个期货模型」是激活步骤而非本轮交付物**（就绪清单见 §六），因为推理中心的四个工作区（截面/个股/治理/滚动）在没有模型时全部走既有的诚实空态（`当前市场无可用模型` 等），不会假装有内容 —— 符合「空就是空」口径。
5. **日历拍板：期货 = CME（新增真定义）**。`model_training._MARKET_CALENDAR['FUTURES']` 早已写 `"CME"`、`marketConfig.ts` calendar 也是 `CME`，只是 `trading_calendar.ALL_MARKETS` 里没有这个键，导致所有期货日历查询走「抛错→吞掉→只看周末」的静默错判。补上 CME 定义让既有的两处声明落地。已知偏差见 §三.3。

## 三、目标架构与设计决策

### 3.1 分层机制（复述，不新增）

```
App.tsx  InferenceCenterByMarket（读 Redux currentMarket）
  ├─ 'CN'      → InferenceCenterPage.tsx       （A股适配器：静态联想表 + normalizeStockCode + SSE）
  ├─ 'HK'      → InferenceCenterHkPage.tsx     （港股：名称表 + normalizeHkCode + HKEX）
  ├─ 'US'      → InferenceCenterUsPage.tsx     （美股：标的池 + uppercase ticker + NYSE）
  └─ 'FUTURES' → InferenceCenterFuturesPage.tsx（期货：品种目录 + 保留原形 + CME）★新增
        ↓ 全部注入
  features/inference-center-shared/（共享壳：InferenceCenterShell + 4 工作区 + hooks）
     · 共享组件里不写 if (market === 'XX')（README 硬约束）
     · 市场差异只经 adapter 契约传入：market/label/calendar/currency/defaultSymbol/联想/K线/归一
```

「加第 N 个市场」三步 SOP 不变：① 写适配器 → ② App.tsx 加分支 → ③ e2e MARKETS 加一项。菜单/路由/权限/国际化零改动。

### 3.2 期货适配器设计（`InferenceCenterFuturesPage.tsx`）

| 契约项 | 取值 | 依据 |
|---|---|---|
| market | `'FUTURES'` | 类型联合扩为 `'CN'\|'HK'\|'US'\|'FUTURES'`（唯一编译期改动） |
| marketLabel | `期货市场` | 对齐「A股市场/港股市场/美股市场」 |
| calendar | `'CME'` | 本轮补 CME 真定义；训练/推理/前端三处早已声明 CME |
| currencySymbol | `¥` | 默认标的为国内主力（RB0.CN），国内为主展示面；国际品种在名称中带单位信息 |
| defaultSymbol | `RB0.CN` | 螺纹钢主力：国内最活跃、数据最全（116 行/日全集内）、中文语料丰富 |
| 联想源 | `GET /api/v1/market-analysis-futures/heatmap?limit=200` | 复用已交付模块的**带缓存**全品种目录（116 项含中文名/板块）：一次拉取，前端模块级 promise 缓存；失败静默降级为空联想，不阻塞手输 |
| K 线 | `GET /market/kline?market=FUTURES`（本模块新增 `inferenceCenterService.getMarketKline`） | `/research/kline` 只分 CN/HK；US 走 `/stock-terminal-us/kline`（同款「不复用坏路径」原则） |
| 符号归一 | 目录快照优先 + 形态启发式 | 见下 |
| toSuffixSymbol | 原样透传 | 期货 symbol 本身即 pred.parquet/因子库落盘形态（`RB0.CN`/`CL.FUT`/`Au99.99`） |

**符号归一规则**（顺序执行，宁可不改、不可改错）：
1. trim；2. 目录内大小写不敏感全等（symbol 或 name）→ 吸附为目录规范形（"rb0.cn"→`RB0.CN`，"螺纹钢"→`RB0.CN`，"au99.99"→`Au99.99`）；
3. 含 `.` → 原样（`RB0.CN`/`CL.FUT` 已是规范形）；
4. `^[A-Z]{1,3}\d{1,2}$`（国内主力形态：RB0/AU0/IF0/T0/PS0）→ 追 `.CN`；
5. `^[A-Z]{1,6}$`（国际品种形态：CL/GC/SI/HG/XAU/S）→ 追 `.FUT`；
6. 其余原样大写（查空即诚实空结果，不猜）。

`Au99.99`/`Au(T+D)` 之类含点或特殊字符的输入**绝不改写大小写**：`quantfutures_hub.fetch_daily_kline` 是 DuckDB 精确匹配 `symbol = '...'`，`AU99.99` 查空（本细案 B5 明确后端 FUTURES 分支保留原始大小写，去大写化只发生在 CN/HK/US 分支）。

### 3.3 三个设计决策与理由

**① 期货日历 = CME（新增真定义，而非 FUTURES→CFFEX）**
- `model_training._MARKET_CALENDAR['FUTURES']='CME'`、`marketConfig.ts` calendar `'CME'`、`model_registry` 的 FUTURES 别名含 CME/SHFE —— 全平台已在文字上指向 CME，本定义让声明落地。
- 期货宇宙是**内外盘混合**（30 国际 `.FUT` + 82 国内主力 `.CN` + 8 上金所），没有单一交易所日历完全正确。实测数据行为：中国节假日周（20261001-07）分区仍写出（仅 29 行国际品种）——**管道按「任一腿开市即写分区」运行**，CME Globex（周日夜~周五、只休美国假日）比 XSHG（休中国节假日）更贴近这个行为。
- **已知偏差（如实记录）**：国内品种在春节/国庆的推断交易日会被 CME 日历判为「开市」。品种级真实交易日应以**数据分区**为准（市场分析模块 `_full_trade_days` 口径）；union 日历（XSHG ∪ CME）留作后续评估项。降级通道仍存在：若 CME 日历越界/缺失，走既有 `SRC_WEEKDAY_FALLBACK` 并在日志留痕。
- 会话定义取 Globex 口径：`17:00 → 次日 16:00（America/Chicago，cross_day）`，日维护休 16:00-17:00。

**② 联想源 = 期货市场分析 heatmap（跨模块复用，而非新端点）**
- 该端点已交付、已缓存（300s）、已含中文品种名（116 项），是「维护也要好维护」的最优解：期货品种目录将来扩充（新合约上市）只需市场分析模块自己的链路更新，推理中心零维护。
- 备选（新建 `/futures/symbols` 端点）会增加第二个品种目录真源，违背 DRY。
- 代价：推理中心期货联想在市场分析模块被移除时会静默退化为空 —— 在 README 的适配器对照表注明依赖。

**③ K 线走 `/market/kline` 补 FUTURES 分支（而非 `/research/kline` 补分支或新端点）**
- `/market/kline` 定位就是「多市场日 K 路由」（`market` 参数文档已写 CN/HK/US/CRYPTO/FUTURES），且已有 `_MARKET_HUB_CFG` 的 hub 直读模式 + 内存缓存（`_kline_cache_*`）。给它补 FUTURES 分支 = 让端点和它自己的文档一致，其余消费方（行情页、仪表盘）未来可直接复用。
- `/research/kline` 是研究域单标的路径，塞期货进去会把「研究域 K 线」与「行情域 K 线」两个口径搅在一起。

### 3.4 空模型诚实态（不装门面）

期货 0 模型时各工作区的实际表现（全部为**既有**行为，本轮只验证不改造）：
- 截面推理：模型下拉空 → shell 渲染「当前市场无可用模型」；预检/排名/历史空态。
- 个股预测：模型列表空 → 「该市场暂无可点名的模型」；手输 RB0.CN 仍可查 K 线（K 线取数先于预测执行，`useIndividualPrediction.ts:260`）；点「执行」若走 execute 路径 → 后端 404「未找到可执行的已注册模型」（清晰错误，非 500）。
- 治理工作区：模型资产数 0；滚动工作区不变。

### 7.3 实施中的偏离（与细案原文不同，均为实测驱动）

1. **CME 会话拆两段（00:00-16:00 + 17:00-23:59:59，非跨夜一段）**：`is_trading_time` 只按本地日期建窗口，`end_at <= start_at` 的跨夜段会被整段推到次日——当日下午 17 点后查不到在盘。两段写法两个方向的边界都落在当日。§3.3-① 的「17:00→次日16:00 cross_day 一段」在实现层不可行。
2. **`_safe_timezone` 别名回退修复（细案外的连带缺陷）**：`_DEFAULT_MARKET_TZ` 键是交易所码，别名市场（FUTURES）查表未命中会落到 `Asia/Shanghai` → 会话整体 +08:00（错 13~14 小时且无声）。探针实测发现后改为「查表未命中 → `get_market(market).timezone` → 最后才兜底沪时区」，并加回归测试。
3. **归一笔⑥ = 「原样」而非原文「原样大写」**：`Au(T+D)` 含括号不含点，若按「其余原样大写」会改成 `AU(T+D)` → 精确匹配查空，与 §3.2 自己对「绝不改写大小写」的告诫矛盾。实现取「原样」，大写只发生在④⑤两条明确裸形态上。
4. **K 线单图态（shared 组件小改，细案外）**：§3.4 写「手输 RB0.CN 仍可查 K 线」，但实测 `StockForecastChart` 嵌在 `prediction` 分支内——0 模型市场 K 线取回来了却**看不见**，且空态文案指引去点不存在的排名榜。`IndividualWorkbench` 增加中间分支：`kline` 有数据而 `prediction` 为空时，K 线上屏 + 一句诚实说明（「当前市场无可用模型：下方为历史 K 线…」/「该标的暂无模型推理结果…」）。对 CN/HK/US 同样生效（预测失败时显示已取到的 K 线而非误导性空态）。
5. **e2e 期货分支的断言取舍**：predict-stock 404 在 0 模型市场是**预期正确回应**（断言其为 404 且非 5xx，而非禁绝接口错误）；货币符号 `¥` 在该分支不断言——K 线单图态下 ¥ 只存在于 canvas 轴标签/hover 提示，DOM 文本里没有，适配器契约由 vitest 锁。
