# 期货市场分析专业化升级 — 侦查与实施细案（2026-10-15）

> 缘起：用户点名「期货市场的市场分析，需要你做的更加专业一些、现在这些界面不够专业，
> 升级版本；前端界面更加专业，最好带预测、直观，专业量化期货分析员用的、生产环境」。
> 本细案 = 三路侦查（后端 feed 面 / 前端现状与 CN 对照 / 预测与模型能力面）+ 数据面实测
> 收据 + 升级设计与实施计划。

## 一、三路侦查收据

### 1.1 现状盘点（2026-10-15 交付基线）

**后端**（`backend/services/api/market_analysis_futures/`，路由 `/api/v1/market-analysis-futures`）：
14 个端点（/status /overview /ranking /heatmap /sector-stats /term /term-ranking /cftc
/oi-changes /receipts /cross-market /precious-basis /refresh /refresh/stream），全部只读
本地 parquet，进程内 TTL 缓存（300s/1800s），`asyncio.to_thread` 转发。

**前端**（`electron/src/features/market-analysis-futures/`，6 Tab ≈1864 行，amber 主题）：
行情总览 / 板块热力 / 期限结构 / 持仓分析 / 仓单库存 / 内外盘基差。视觉基线尚可，
但信息扁平、无下钻联动、无预测面、无质检可信面。

### 1.2 专业量化期货分析员的参照系（业界惯例内容清单）

| 维度 | 专业惯例 | 我们现状 |
|------|---------|---------|
| 期限结构 | 曲线 + **年化展期收益（carry/roll yield）** + 距到期 | 只有近远月价差 %（未年化） |
| 现货基差 | 基差率 + 历史分位（期限结构溢价的地面真值） | 仅贵金属 2 组自算，52 品种现货基差数据零消费 |
| 库存周期 | 库存分位 + 累/去库方向（theory of storage） | 仅 CZCE 仓单两日增减榜 |
| 席位/持仓 | 会员多空榜、集中度、席位变化（hedging pressure） | 数据已落盘（33 品种）零消费；CFTC 仅国际 |
| 展期成本 | 保证金/手续费/乘数、真实成交额 | 乘数为静态常量；成交额为估算 |
| 大盘与合约面 | 商品指数基准、到期日历、交割窗口 | 全部缺失 |
| 前瞻面 | 多因子截面视角（carry/基差/库存/动量/季节性） | **完全缺失** |
| 数据可信面 | 数据新鲜度与覆盖显形 | /status 有部分字段但前端不显 |

### 1.5 预测能力面结论（为什么本期不引入模型层）

期货预测面 = 「就绪的空壳」：训练/推理/因子数据集三条管道市场路由齐备，但 0 模型、
0 信号行；CN 因子概率板的候选池/模型信号层/行业成员/交易掩码/regime 全部 CN 强耦合，
移植需重标定（117 品种小截面 vs 5000 股票，阈值全部失效）；首个期货模型训练属独立工程
（数据修复 + 训练 + 小截面阈值重标定），不该混入本次 UI/分析升级。

**本期"预测"的定位** = **商品期货学术与业界验证的多因子前瞻视角**（截面分位合成，
数据全部本地现成、当日可算）：carry/展期收益、现货基差分位、库存周期、动量、季节性
——这正是专业商品期货 desk 的一线工作语言。方向诚实、无需模型、生产可维护。
模型增强（train → engine_signal_scores market=FUTURES → 概率板模型广度列）登记为后续。

### 1.6 顺手抓到的三个生产缺陷（升级前置修复）

1. **l1_factors 分区冻结（训练数据量级缺陷）**：`build_l1` 增量「已有分区一律跳过」
   （build_ml_l1_dataset.py:136-137），而 daily_forward 是**按品种滚动落盘**的——凌晨先到
   的 2 行（FCPO/RSS3）分区被冻结，后来 116 行全量补写不再进 l1。实测最近 90 个分区仅
   12 个完整、23 个只有 2 行。修复 = 窗口内分区改「merge 合并去重」语义（幂等），随后
   一次常规增量即自愈近 190 日全部缺陷分区。
2. **contracts_daily 曲线深度只有 3 个月**：抓取窗口未来月 2 → 12（`range(12, -3)` →
   `range(12, -13)`），一次性补跑（~80 品种 × 10 新增月 ≈ 800 请求），修复后期限结构
   曲线 3 点 → 至多 14 点。
3. **inventory.py:127 sector 取参 bug**：`symbol_meta(f"{variety}0.CN")` 误用外层参数
   `variety`（循环变量已改名 variety_name 但此处漏改）→ 无参调用全部行 sector 落到
   `None0.CN` 兜底。修复 + 回归测试。

**/receipts 502（探针实测）**：HTTP 复测 200/1.2s；定位为 API 子进程热重载窗口内的瞬态
502（共享工作区并行会话保存文件触发），非端点缺陷。前端错误态加「重试」按钮兜底。

### 2.2 前瞻视角（核心设计）

**因子集（5 个入合成 + 1 个纯事实展示）**：

| 因子 | 数据源 | 计算 | 覆盖 | 样本深度 |
|------|--------|------|------|---------|
| carry_annual 年化展期收益 | contracts_daily（加深后）+ contract_meta | ln(近月/远月) × 365 / 到期日差；near=首个活跃、far=最远活跃（与 term.py 同口径）；到期日取 contract_meta last_trade_date，缺失回退交割月首日 | 80 品种（曲线 ≥2 点） | 250 交易日（自建历史） |
| basis_pct 现货基差分位 | spot_basis | dom_basis_rate 在自身 250 交易日的截面分位 | 52 品种 | 2 年（464 分区） |
| inv_chg_pct 库存变化分位（反向） | inventory_em | 20 日库存变化率在全历史分位，**方向取反**（去库=偏强，theory of storage） | 59 品种 | ~270 日（2025-09 起，显形） |
| mom_20d_pct 动量分位 | daily_forward .CN | 20 日收益截面分位（主力连续口径，换月跳空标注） | 82 品种 | 全史 |
| seasonality 同月效应 | daily_forward .CN | 历史同月平均月收益的截面分位（duckdb 列裁剪读 8 年窗口） | 82 品种 | 8 年 |
| member_net 席位净多变化（**不入合成**） | member_rank_sina | 前 20 名多−空净额及日变化，纯事实展示 | 33 品种 | 仅 6 日 → 样本不足以谈分位，诚实降低参与度 |

**合成规则**：各因子截面 rank_pct(0-100) → 等权平均（缺失剔除、权重重归一）；
覆盖 <2 因子的品种 composite = null（「—」显形，绝不排名半张桌子）。
三档判定（与 CN 概率板 q67/q33 口径一致）：**靠前（≥q67）/ 居中 / 靠后（≤q33）**。

**展示纪律（沿平台军规）**：展示面只说位置（靠前/靠后/居中）+ 0-100 截面分位数值；
**不给"买入/卖出"、不写"概率"、不承诺收益**；缺失一律「—」；席位/库存短样本显形
sample_days；口径卡（可展开）写清因子定义/数据源/方向与局限——含一句规范声明：
「carry 与基差溢价是商品期货文献广泛验证的截面收益相关因子，本板为历史统计口径
的分位视角，不构成收益承诺与投资建议」。

**品种画像下钻**（行点击 → 同页右侧画像，面包屑返回）：期限曲线 + carry 250d 历史、
基差 2 年历史 + 分位带、库存 1 年历史 + 20 日变化、价格/持仓 120 日双轴、席位（若有）。

## 四、口径与边界声明

- 前瞻视角为**历史统计口径的截面分位视角**，非投资建议、非收益承诺；不输出买卖词汇。
- 主力连续（.CN）为新浪主力代码拼接，换月存在跳空，动量口径标注。
- 生意社现货基差存在源侧噪声（个别品种现货与盘面脱钩），分位口径天然稳健化。
- 席位覆盖仅 SHFE/CZCE（DCE/CFFEX/INE 无免费源）；样本 6 日开始，页面显形。
- 库存为东财口径（单位随品种），只做相对分位与变化，不做跨品种绝对值比较。
- 真实成交额 = exchange_daily（交易所官方）最新完整日；SHFE/DCE/GFEX 仓单源失效，
  仓单仅 CZCE，页面如实标注。
