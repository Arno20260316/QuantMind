# 策略「不能启动」的提醒面 细案（2026-10-13）

> 缘起：用户报「实盘交易 策略尚未模拟验证（VERIFIED）：REAL 须先经模拟盘（SIM）验证」，
> 问「启动策略这样了、不能启动吗？」，并明确指出：**不能启动时前端也要有提醒，不然搞不清楚**。
> 本细案把「启动被门禁拦下」从**一次性的 toast** 升级为**启动前可见 + 失败后常驻**的双面提醒，
> 并让「策略库」页的晋级门槛卡同时给出进模拟盘 / 进实盘两道门禁的逐项拆解。

## 一、侦查纪要（实证）

| # | 事实 | 位置 |
|---|------|------|
| 1 | 启动有**两道**门禁：① 生命周期状态机（SIM 须 VERIFIED、REAL 须 SIM/LIVE）；② 回测体检晋级门禁（SIM 须体检 A/B；REAL 再加 SIM≥20 交易日 + 跟踪误差≤15%） | `backend/shared/strategy_lifecycle.py::can_start`、`backend/shared/backtest_health.py::promotion_gate` |
| 2 | 两道门禁在 `/start` 均抛 **400 + 纯字符串 detail**（`real_trading_lifecycle.py:425`、`:460`） | 前端 `resolveErrorMessage` 只能转成 `message.error(...)` **瞬时 toast**，转瞬即逝、无下一步指引 |
| 3 | 交易准备度不通过的 409 已是**结构化 dict**（`precheck_failed: True`），前端有 `extractTradingPrecheckFailure` 会打开常驻 preflight 弹窗 | `real_trading_lifecycle.py:541`；对比之下，两道门禁的 400 是**唯一没结构、没常驻面**的拒绝 |
| 4 | 后端 `/api/v1/strategies` **已回传 `base_status`**（DRAFT/VERIFIED/SIM/LIVE 展示词表），但前端 `toStrategyFile` **把它丢掉了**，`StrategyFile` 也没有该字段 | `user_strategies.py:424` vs `strategyManagementService.ts:48`、`types/backtest/strategy.ts` |
| 5 | `CommandBar` 的启动按钮只认 `selectedStrategy?.is_verified`，**无启动前资格可见性**；按钮文案 `未经验证` 无法表达「verified 但进不了实盘」 | `CommandBar.tsx:81,181` |
| 6 | `/api/v1/eval/health/{strategy_id}` 已回传**门禁预演**（`build_gate_preview`），但**硬编码 `mode="SIMULATION"`**，无 REAL 预演、无生命周期行 | `eval_scores.py:58,523` |
| 7 | `/start` 成功后会 `_schedule_status_writeback(lifecycle_status="SIM"/"LIVE")`（`real_trading_lifecycle.py:711`），停止后回写 `VERIFIED`（`:913`）——所以「先切模拟启动一次」确实是可行出路 | `real_trading_utils.py::_schedule_status_writeback` |

**结论**：缺口只有两处——(a) 两道门禁 400 只有纯字符串；(b) 启动前没有资格面 + `/health` 的门禁预演只覆盖模拟盘。其余链路（状态回写、体检留档、sim_start 打点）都已具备。

## 二、改动清单

### A. 后端：启动资格清单（唯一实现，供展示面与执行面同源）

- 新增 `backend/shared/start_eligibility.py`
  - `build_start_eligibility(*, status, health, mode, sim_trading_days, tracking_error, health_gate_enabled=True, source="user_strategy") -> dict`
  - 逐项列出：`lifecycle`（生命周期状态）、`health`（回测体检）、REAL 专属 `sim_days`（模拟交易日）、`tracking_error`（跟踪误差）；
  - 判据**全部复用** `can_start` / `promotion_gate` / `SIM_REQUIRED_VERDICTS` / `LIVE_SIM_MIN_TRADING_DAYS` / `LIVE_MAX_TRACKING_ERROR`（不新增阈值）；
  - `source != "user_strategy"`（`sys_` 模板 / 文件上传）→ 直接放行（与 `/start` 一致，不吃状态机与体检门禁）；
  - 返回 `{allowed, mode, items:[{key,label,value,passed,reason,next_step}], next_step}`。
  - 纯函数，无 IO → 可单测（含「SIM 可启动 / REAL 被拦」矩阵）。

### B. 后端：两道门禁的 400 改结构化 detail（保留人话 message）

- `backend/services/live_trading/routers/real_trading_lifecycle.py`
  - 生命周期门禁（`:425`）与体检门禁（`:460`）的 detail 由纯字符串升级为
    `{"message": <原人话>, "gate": "lifecycle"|"promotion", "mode": <mode>, "gate_items": [...], "next_step": <下一步>}`；
  - `message` 字段与原来**逐字一致**（`realTradingService.resolveErrorMessage` 已优先取 `detail.message`，文案不回退）。

### C. 后端：`/eval/health/{id}` 补 REAL 预演 + 生命周期行

- `backend/services/api/routers/eval_scores.py`
  - `GET /health/{strategy_id}` 新增 `mode` 查询参数（默认 `SIMULATION`，向后兼容）；
  - 新增返回 `eligibility: {"SIMULATION": {...}, "REAL": {...}}`（两个 mode 的完整资格清单）；
  - 保留 `gate`（= SIMULATION 预演）不动，`HealthArchivePanel` 等既有消费方零改动；
  - SIM 交易日 / 跟踪误差经 `trade_shared.redis_client.get_redis` 尽力读取（失败 → `None`，按既有「无数据只提示不拦」口径）。

### D. 前端：启动前资格条 + 按钮禁用理由（双面之「启动前」）

- `electron/src/services/strategyManagementService.ts` + `types/backtest/strategy.ts`
  - `toStrategyFile` 透传 `status`/`base_status`（后端已发，不再丢）。
- 新增 `electron/src/pages/trading/tabs/StrategyConsole/hooks/useStartEligibility.ts`
  - 选中策略 + 当前 mode → 读 `/eval/health/{id}` 的 `eligibility[mode]`；未选中/内置模板 → 直接放行。
- `CommandBar.tsx`
  - 顶部状态条下方新增「启动资格」条：逐项 ✓/✗ + 下一步；不满足时按钮禁用并给**悬停/可见理由**；
  - 新增 prop `startEligibility`；禁用判据从 `!is_verified` 收敛为「资格清单 allowed」。
- `TopologyConsole.tsx`
  - 组 `startEligibility`（复用 hook）并下传 `CommandBar`。

### E. 前端：启动失败常驻弹窗（双面之「失败后」）

- `electron/src/services/realTradingService.ts`
  - 新增 `extractStartGateFailure(err)`：识别 `detail.gate_items` → `{message, gate, mode, items, next_step}`。
- `RealTradingPage.tsx`
  - `executeDeploy` catch 内：命中 `extractStartGateFailure` → 打开**常驻**弹窗（非 toast），列出逐项 ✗ 与下一步；已有 preflight 失败弹窗路径不动。

### F. 前端：策略库晋级门槛卡补全（双门禁 + 生命周期行）

- `PromotionGateCard.tsx`
  - 展示「晋级门禁（进模拟盘）」与「晋级门禁（进实盘）」**两行**，各带逐项拆解（生命周期 / 体检结论 / 模拟天数 / 跟踪误差）；
  - 修正现有**反色**：`allowed=true` 现渲染成红色告警（应绿/中性）、`allowed=false` 渲染成灰（应告警）;
- `types/evalCenter.ts` + 服务层：新增 `eligibility` 类型（`gate` 保留）。

## 三、验收

1. 后端单测：`backend/tests/test_start_eligibility.py`（新）覆盖 SIM 可启动 / REAL 缺 SIM / 无体检 / L/E / 未开体检门禁 / 模板放行；`ruff check` + `ruff format --check`。
2. 现有回归：`test_strategy_lifecycle.py`、`test_backtest_health.py`（含 `promotion_gate(` / `latest_strategy_health(` **源码字面量断言**不得破坏）、`test_live_trading_gate.py`。
3. 前端：`npm run typecheck` + `vitest`（新增 `startEligibility` 纯函数用例；`RealTradingPage`/`tradingModeCopy` 既有用例不回归）。
4. 部署：`bash scripts/deploy_frontend.sh`（本机需 `VITE_ENABLE_REAL_TRADING=true` 与 `--allow-local-live`），浏览器强刷实测：选一个 VERIFIED 策略 → 顶部出现「不可启动实盘 · 缺 1 项（生命周期）」→ 点启动 → 常驻弹窗给出「先切模拟启动一次」。
5. 真机/接口探针：`curl` 直接打 `/real-trading/start` 于 VERIFIED 策略，确认 400 信封含 `gate_items`。
