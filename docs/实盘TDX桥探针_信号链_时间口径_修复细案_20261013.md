# 实盘 TDX 桥探针 / 批量信号链 / 时间口径 修复细案（2026-10-13）

> 缘起：用户报「实盘实时数据获取不到、系统健康很多警告、看盘时间不对、策略启动不了、信号分布异常（CN 最新日仅 562 行实时行）」。
> 侦查结论见下「一、侦查纪要」。本细案只动**根因**，不做展示层装饰。

## 一、侦查纪要（实证）

| # | 现象 | 根因（已实证） |
|---|------|----------------|
| 1 | `TDX 桥不可达: timed out` | 客户端探针 `check_tdx_bridge_online()` 超时 **3.0s**，桥自身 TDX 调用预算是 `TDX_CALL_TIMEOUT = 8.0`（实测量到 6–35s）。3s 预算系统性低报：9/10 恰好 3.05s 超时；放宽到 30s 全部 200。**桥是活的**——同刻 `check_bridge_account_channel()`（12s 预算）稳定返回「账户通道已连接（持仓 4 条）」。 |
| 2 | 「策略也启动不了」 | `/real-trading/start` 复用 `run_trading_readiness_precheck`，不过即 409。唯一失败项 `qmt_agent_online`。TDX 用户无 QMT 心跳属**预期正常**，是 #1 的 3s 行情探针在同一刻超时，把「可回退通道」拼成「双失败」（`f"{qmt_detail}；且 {tdx_detail}"`）。16:00 复测 `passed=True`。 |
| 3 | 信号分布 C01/C02 fail/warn | 全链：`alpha_library_refresh.sh` 02:30 内存闸跳过（可用 14GB < 30GB）→ alpha 停在 `dt=20261009`（日K 已 `dt=20261012`）→ CUSTOM 重建 fail-closed 拒写 → 钉在 `/data/quantcustom` 的模型撞「主模型维度门禁未通过…超出数据范围」→ 08:00 六次 `celery_auto_inference_if_needed` 全 failed → 当日无 batch 信号。 |
| 4 | 桥 429 刷屏（近 6h 175 次） | 设计预算 600/min，热集轮转自身 ~333/min，与持仓馈送/账户同步/推送共用。**仓库 `config.yaml` 默认写 `rate_limit_per_minute: 60`**，与部署端 600 及设计预算矛盾（自带配置起桥必自锁）。 |
| 5 | 顶栏时钟比北京快 1 小时 | 主机 TZ=Asia/Tokyo，`HeaderBar` 顶栏时钟走设备本地 `new Date().getHours()`，绕过既有唯一口径 `timeBeijing.ts`。同类未收口处还有 desk as_of / DeskCards 新鲜度 / 实时推理节拍 / StrategyConsole 各「更新于」/ 市场分析「数据更新于」。 |
| 6 | C13 真日历 XSHG 仅到 2026-12-31（剩 79 天） | 次年 A 股放假安排国务院年底才印发，属**数据/运维**项，非代码 bug。 |

## 二、改动清单

### A. 桥探针超时对齐 + REAL 闸门改以「账户通道」为准（生产语义修正）

- `backend/services/live_trading/routers/real_trading_utils.py`
  - 新增 `BRIDGE_HEALTH_TIMEOUT_S = 12.0`（与 `BRIDGE_ACCOUNT_TIMEOUT_S` 同档，**必须 > 桥的 8s**），`check_tdx_bridge_online()` 用它替换硬编码 `3.0`。
- `backend/services/trade/services/trading_precheck_service.py`（REAL 分支）
  - 回退判据从「行情半边 health」改为「账户通道真查一次」：`account_ok` 决定 `qmt_ok`；`check_tdx_bridge_online()` 降级为**文案补充**（说清是行情半边还是账户半边断的）。保持 `bridge_account_channel` 独立成行不变。
- `backend/services/live_trading/routers/real_trading_preflight.py`
  - 同上：`qmt_agent_online` 回退分支与 `tdx_channel_ready`（多空灰度跳过判据）都改走账户通道。

**为什么**：账户通道是唯一能判「行情通 ≠ 账户通」的真探针（既有 `test_tdx_bridge_account_channel.py` 已锁此纪律）。让 3s 的行情探针决定「策略能不能开」是判据错位。

### B. api 代理慢路径放行 precheck/preflight/account

- `backend/services/api/routers/trade_proxy.py`
  - `_resolve_proxy_timeout` 的放宽名单从 `("/manual-executions",)` 扩为 `("/manual-executions", "/trading-precheck", "/preflight", "/account")`，常量具名化。
  - 依据：实测 `trading-precheck` 18.7s、`account` 27.2s，均 > 全局 10s → 日志 34 / 104 次 `ReadTimeout` 假失败。

### C. 桥限流默认值与设计预算对齐

- `tools/bridge-windows/config.yaml`、`tools/bridge-windows/dist/config.yaml`
  - `security.rate_limit_per_minute: 60 → 600`（与部署端、热集设计预算一致）；加注释说明热集轮转占 ~333/min。
- `backend/services/live_trading/services/tdx_hot_set_feed.py` 模块 docstring 补「预算三处口径」注记。

### D. alpha_library 内存闸：跳过 → 有界等待；并把重试 cron 落机

- `scripts/alpha_library_refresh.sh`
  - 内存不足时**轮询等待**（`MEM_WAIT_SECONDS` 上限内），超时才跳过；跳过日志带可用内存与等待时长，便于 `pool_readiness`/告警面识别。
- 宿主 crontab 补 `scripts/alpha_refresh_retry.sh`（c402f031 已交付脚本但**未落机**）：
  - `30 5 * * 2-6`、`30 6 * * 2-6`（JST，接在 quantdb 夜间同步与 CUSTOM 03:00 CST 派发之后）。
  - 改 crontab 前先备份 `crontab -l` 到 `logs/keepers/crontab.bak.<ts>`。

### E. 日历（不写码，待官方清单）
XSHG 次日安排公布后执行 `python backend/scripts/seed_trading_calendar.py --year 2027 --holidays-file <清单> --apply`。**不臆造节假日**。

### F. 时间显示统一北京口径

- `electron/src/utils/timeBeijing.ts`：新增 `fmtBeijingDateEnShort(value)`（英文月/日/年短式，供顶栏用）。
- 收口以下设备本地时钟：
  - `electron/src/components/layout/HeaderBar.tsx`（顶栏时钟 + 日期，加「北京」标识）
  - `electron/src/features/desk/DeskTodayPage.tsx`（as_of chip）
  - `electron/src/features/desk/components/DeskCards.tsx`（数据同步新鲜度时刻）
  - `electron/src/features/desk/services/realtimeInferModel.ts`（`_hms` 节拍）
  - `electron/src/pages/trading/tabs/StrategyConsole/**`（CommandBar / GuardianStrip / RhythmLayer / RuntimeLayer 的「更新于/最近周期」）
  - `electron/src/features/market-analysis/pages/MarketAnalysisPage.tsx`（数据更新于）

### G. 时段常量（不改码，仅定性）
「三套时段」实为**两类用途**，非同一判据的三份抄写：
- **展示口径**：`shared/market_sessions.py` CN 与前端 `marketConfig.MARKET_SESSIONS_UI` CN **已一致**（09:30–11:30 / 13:00–15:00）。
- **闸门口径（含集合竞价/尾盘缓冲）**：后端 `trading_session.TRADING_SESSIONS`（09:15–11:35 / 12:55–15:05）、前端 `isCnTradingHours`（09:25–11:35 / 12:55–15:05）、`real_trading_preflight._is_cn_trading_hours`。
盲目收敛会改实盘闸门行为，**本细案不动**，仅在报告中列出待议。
