## 1. 侦查事实（全部实测，非推测）

### 1.1 「1380」的两个成因

1. **产物滞后**：`factor_selection.json` 生成于 2026-09-14，页面计数就来自它；
2. **结构缺口**：筛选器只吃带 `report/factor_report.json` 快照的库，`REPORT_DATASETS`
   硬编码 7 个（alpha_library/tdxgs/jq110/alpha360/l1_factors/l2_factors/gap_mined）。
   1380 = 六库快照 1307 + 旧研究库 73，**分毫对得上**。

### 1.2 私人库 4011 的精确构成（13 个 l1 分组）

factor1300 1125 · factor_defs 1098 · Alpha 因子库 429 · Alpha360 360 · 候选因子池 238 ·
L2 211 · RD-Agent 122 · L1 110 · 聚宽 109 · 通达信 88 · 空档挖掘 69 · 每日特征 44 ·
l1_batch1_factors 8。

### 1.3 关键实测（决定了改动面）

| 事实 | 实测 |
|---|---|
| **cand_factors ≡ factor_defs 缺的 238 列** | `快照1336 − 私人组1098 = 238`，与 cand_factors 238 列**集合双向相等**。私人库扫描按字母序 cand 在 factor_defs 前先到先得 —— 筛选去重必须同序 |
| **features_daily 含 6 个前视收益标签** | `future_return_{1,3,5,10,20,60}d` 是数值列，会进扫描；私人组 44 里实测含这 6 个（taxonomy 归「其他/非因子」）。**若进筛选 |IC|≈1 必霸榜入选 kept → 训练面板泄露**，快照层必须排除 |
| **features_daily 列代际三朝** | ≤20260630 分区 50 列（含旧名 `return_Nd` + `Symbol_val/close_val`，**无** is_st/free_float_shares）；20260918 分区 78 列（`return_Nd` 仍有）；20260930+ 改名 `future_return_Nd` |
| **features_daily 的 close 与 l1 同口径** | 同日同股（20260930，5210 交集）比值恒 1.000000，std=0 → `close_fwd` 可用 |
| **cand_factors close 同口径** | 20260918 对 l1 比值恒 1.000000 → `close_fwd` 可用；schema 2604 分区稳定 246 列 |

### 1.4 两处代码对代际断层的既有行为（会炸/会静默）

- **构建器 worker**：`merged[cols]` 固定列取数 —— features_daily v1 分区缺
  is_st/free_float_shares → KeyError 直接炸构建；
- **筛选器联合相关**：`pd.read_parquet(columns=["symbol", *names])` 缺列抛异常 →
  `except: continue` 静默跳过整个块 → 若不改，features_daily 全部因子在 82 个月末
  里只有 ~5 期可比 → min_periods=50 全军 NaN → **一个都不去重、直进 kept**。

## 2. 方案（改动面）

### 2.1 `backend/services/engine/factor_report/datasets.py`（+3 条注册）

- `cand_factors`：close_fwd，meta=_ID_COLS+_OHLCV_COLS，build_start=20160104；
- `features_daily`：close_fwd，meta=ID+close+close_val+**两代 return 标签列 12 个全列**，
  build_start=20160104；
- `l1_batch1_factors`：close_fwd_donor→l1_factors，build_start=20160219。

### 2.2 `backend/scripts/build_factor_report.py`（1 处）

worker 取数 `merged[cols]` → `merged.reindex(columns=cols)`：缺列补 NaN 列、
多余列丢弃、列序不变。NaN 列 = 全退化因子，下游（gram/IC/报告 null 净化）已有
factor1300 全退化先例，按现有口径落 null。is_st/free_float_shares 只在近月分区存在，
其 IC 只覆盖有值窗口（如实展示，report 侧已有「—」口径）。

### 2.3 `backend/scripts/screen_factors.py`（5 处）

1. `REPORT_DATASETS` 扩到 13 库，**顺序 = discovery.AUTO_PRIORITY + 字母序**
   （l1,l2,alpha_library,alpha360,jq110,tdxgs,features_daily,cand_factors,factor1300,
   factor_defs,gap_mined,l1_batch1_factors,rd_mined），与私人库扫描先到先得逐字同序；
2. 跨库重名：删 `SystemExit`，改**先到先得去重**（提取纯函数 `_dedup_first_wins`，
   子矩阵 `np.ix_` 同步裁剪，逐库打印让位数）；metrics 改 setdefault（首见为准，
   与去重口径一致——否则 factor_defs 会覆盖 cand 那 238 个的展示元数据）；
3. `_union_cross_corr` 分区读取加降级：缺列时按可用列交集读 + `reindex(columns=names)`
   补 NaN（代际断层下 features_daily 仍有全期可比）；
4. `DATASET_LABEL` 补 6 个新库标签。
5. **「先门槛、只算候选列 + 按日期并行」**（执行前预演后追加）：全宽 4078 列 corr
   实测 249s/期 × 82 期 ≈ 5.7 小时。pandas 逐对 Pearson 与矩阵里还有哪些列无关 →
   候选子矩阵与全宽矩阵**逐位相等**（预演 150 列 vs 300 列切片已证）；先过门槛再
   算相关把 O(k²) 从 4078² 压到候选 2520²，再按日期 fork 池化（`--cross-workers`，
   默认 min(8, CPU)），imap 保序累加 → 与串行**逐位一致**（预演已证）。缓存
   cross_corr.npz 改存候选列，支持子集切片复用（完全一致→直用 / 候选 ⊂ 缓存 →
   按位切片 / 其余→重算；切片合法性同源于逐对独立）。
