定性：**迁移断链修复 + 上游功能全量回归**（用户令：「是都需要迁移回来的！功能不能少了」「这个是总控，你变成只读了、全部给我调整回来」）

## 〇、一句话诊断

上游 quant-Trader 的 `scripts/live_hourly_analysis.py` 是**一个脚本同时做完六件事**：
分析（写 `log.jsonl`）→ 决策 → 闸门 → 桥下单 → 分账记账（写 `position.jsonl`）→ 净值采样。
每 agent 每小时一轮，**对话与下单是同一个回路**。

迁 QM 时这个回路被**拆成了两半，且两半各自断了一条腿**：

| | 分析/对话 | 决策/下单 | 分账记账 | 落盘 |
|---|---|---|---|---|
| **决策轮**（trade 常驻） | 只有 JSON-only 提示词，无四段式 | ✅ 完整（闸门 20+ 条齐全） | 写 PG `qm_agent_ledger_*`，**冻结在 10-09** | ❌ **不写 arena 任何文件** |
| **对话轮**（宿主 cron） | ✅ 有分析 | ❌ **只读，明令不下单** | ❌ 不记 | ✅ 只写 `log.jsonl` |

于是 arena 前端的三个 tab 各自对着一个**没有写侧的文件**：

- **成交/持仓/净值** tab ← `position/position.jsonl`：**全仓无写者**，冻结 2026-09-29 23:48
- **模型对话** tab ← `log/{date}/log.jsonl`：有写者但**是被阉割的只读轮**，输出无四段式 → 「总结没有」
- 分账台账（PG）：写者只有两条真单通道，**TDX 桥链路一条都没接**

用户四条抱怨，全部由这一张图解释。

## 一、事实基座（全部实测，非推断）

### 1.1 文件面冻结

```

  → 最后写入 2026-09-29 23:48:54
data/agent_data_astock/{market-research,news-*}/log/**/log.jsonl
  → 最后写入 2026-09-29
```

全仓 grep：`position.jsonl` **只有读取方**（`agent_arena/agent_data.py`、`trade_store.py`、`arena_config.py`、`agents_family.py`），**零写入方**。
上游写者是 `quant-Trader/agent_tools/tool_trade.py:174`（buy）/ `:373`（sell）。

### 1.2 行格式（写入侧必须逐字节满足的契约）

`position.jsonl` 每行：
```json
{"date":"2026-10-14","id":12,
 "this_action":{"action":"buy","symbol":"600338.SH","amount":800},
 "positions":{"600338.SH":800,"CASH":91234.56}}
```
- `this_action` 缺省 = 非交易行（净值采样行不带该键）；`load_trades` 靠它筛成交
- `date` 兼容 `YYYY-MM-DD` 与 `YYYY-MM-DD HH:MM:SS`
- 代码用**后缀式**（`600338.SH`）——与 PG 面的前缀式不同，转换走 `StockCodeUtil.to_suffix`

`log.jsonl` 每行：
```json
{"timestamp":"2026-10-14T13:02:19.634463+08:00","signature":"glm-5.3-flash",
 "new_messages":[{"role":"user","content":"<完整提示词>"},
                 {"role":"assistant","content":"<LLM 原文>"}],
 "usage":{"prompt_tokens":1104,"completion_tokens":3819,"total_tokens":4923}}
```
- `usage` 是**必须键**：`agents_family.py:330` 的 `/token-usage` 端点只统计带 `usage` 的行
- 前端 `parseAnalysis.ts` 靠 `①|【总体总结】` / `②|【分析链路】` / `③|【推理论证】` / `④|【决策】` 切四段；**无标记则回退**「摘要=首段」，实测 deepseek-v4-pro 全轮回退失败 → 总结空白
- `④` 段内的 JSON 对象被 `extractJsonBlocks` 抠出来渲染成决策卡
