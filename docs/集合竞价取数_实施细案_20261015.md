# 集合竞价取数 实施细案（2026-10-15）

> 需求（2026-10-15 用户）：**实盘持仓股票 ∪ 准备要买的股票（当日候选池）用新
> TdxAiData 接口获取集合竞价数据**。触发来源 = TdxAiData 官方公众号文章
> 《get_call_auction_batch 集合竞价逐笔数据》。

## 1. 数据源事实（已实测核验）

- SDK：`/opt/tdx-aidata` **v1.2.2**（2026-09-30 发布，`__init__.py:18` 版本号），
  CHANGELOG 1.2.2 新增 `get_call_auction` / `get_call_auction_batch` 与时段参数。
  宿主目录同挂载进任务容器，worker 子进程 CWD 即 SDK 目录。
- 接口：`tqs.get_call_auction_batch(stock_list, field_list=[], type=1)`。
  - `stock_list`：**带市场后缀**（`600036.SH`）；`type=1` 仅早盘
    （09:15:00–09:24:5x，实测 ~70 条），`type=0` 早盘+尾盘（含 14:57–15:00）。
  - 返回：每代码一个 dict，四列**按下标对齐的字符串嵌套列表**——
    `Time`（撮合时间 HHMMSS）/ `Price`（虚拟匹配价）/ `Volume`（虚拟匹配量）/
    `LeaveQty`（未匹配量，**可为负=卖压**）。
  - 未开盘/无竞价记录 → 空 dict（经 worker `_capture_fd_call` 判定为**合法空**）。
- **日期盲陷阱（2026-10-15 08:18 实测）**：今日竞价开启前调用，SDK 返回的是
  **上一交易日**的完整早盘序列（09:15:02→09:24:59，60–169 条/只），记录里
  **没有任何日期字段**。防御 = 双闸：任务是只 09:15:30 起的档期取数（盘前不
  落盘）；且 `guard_stale_rows` 按时间不可能性（末帧晚于当前时刻+30s）判陈旧
  **显式丢弃**，证据（`stale_dropped_rows`/`stale_last_time`）进 summary 绝不
  静默。**残差**：09:25:05 档对停牌股若 SDK 仍给昨日序列，时间上与今日重合不
  可判别——观测面 = 该票 09:20:30 档是否被守卫判陈旧。消费面读
  `qm:call_auction:{day}` 时，信任「档期采样+守卫」的时序保证，不要拿内容猜日期。

## 2. 通道接入（`backend/shared/tdx_aidata/`，3 处）

worker 是 SDK 唯一引入口（源守卫测试锁定），业务一律走 IPC：

| 文件 | 改动 |
|------|------|
| `protocol.py` | `KNOWN_METHODS` 登记 `"get_call_auction_batch"`（编解码白名单，:304/:321 校验） |
| `worker.py` | `_invoke` 新分支：symbols 必填、type 透传、`_capture_fd_call` 包裹；空结果+有 fd 输出 → `__sdk_error__`，空+无输出 → 合法空 dict |
| `client.py` | `TdxAiDataClient.get_call_auction_batch(symbols, type=1, timeout=60)` 便捷方法 |

预算闸门（`_BudgetGate`，默认 30 请求/窗口）对数据类方法自动生效，无需另配。

## 3. 采集任务（`backend/services/live_trading/services/call_auction_watch.py`）

trade 常驻任务（`trade/main.py` lifespan 注册，随服务起停）。

### 名单口径（用户原话的翻译）

**实盘持仓 ∪ 当日候选池**，两源失败互不阻断（errors 如实进状态）：

- 实盘持仓：`shared.real_positions.load_real_positions`（多券商并集唯一实现），
  租户 `QM_HOT_SET_REAL_TENANT`（默认 default）、用户 `QM_HOT_SET_REAL_USER`
  （默认 10000001，与热集/账户后台同解析）。
- 当日候选池：`shared.decision_context_source.load_pool_doc`（决策轮同源）。
- 合并键 = 后缀式（SDK 口径），双源命中 → `roles: ["holding","candidate"]`。
- 名字：持仓 payload `stock_name` → 池行 `name` → `stock_name_mapper.resolve_name`
  兜底；都没有为空串（展示回退代码，绝不编）。

### 采样档（北京时间）

`SAMPLE_TIMES = ("09:15:30", "09:20:30", "09:25:05", "15:00:05")`，
对点后 `SAMPLE_GRACE_S=120s` 宽限补采，`MAX_ATTEMPTS_PER_SAMPLE=3` 防配额风暴。
**每档调用返回的都是从 09:15:00 起的全序列**——后档天然包含前档，进程晚起
最坏错失「竞价演化」的即时视图，不丢数据本体。收盘档 `type=0`（含尾盘竞价），
其余 `type=1`。轮询 5s（`QM_CALL_AUCTION_WATCH_INTERVAL_S` 可调）。

### 落点

- Redis（**交易库 db2**，`trade_shared.deps.get_redis`）：
  - `qm:call_auction:{YYYYMMDD}` Hash：field=**前缀码**（平台 Redis 键约定），
    value=`{name, roles, summary, sample, at}` JSON；TTL 7 天。
  - `qm:call_auction:status`：任务心跳/体检（targets/holdings/candidates/
    rows_total/errors/archive）；TTL 2 天。
- 归档：`{QM_CALL_AUCTION_ARCHIVE_DIR:-/data/call_auction}/date=YYYYMMDD/
  sample-HHMMSS.json`——逐笔全量 rows + 摘要，**原子写**（tmp+rename），
  与 L0.5 落盘同款 date= 分区。

### 状态机

- 非交易日各档秒过（`daily_pnl_report_task._is_trading_day` 同口径）。
- 无名单 → 本档作罢（合法，记状态）。
- 单档 fetch 失败 → 下一轮（5s 后）宽限内重试，3 次仍败 → 本档放弃并告警日志。
- 循环整体 try/except 兜异常不退出；`CancelledError` 上抛。

### 开关与运维

- `QM_CALL_AUCTION_WATCH_ENABLED`（默认 `true`）。
- 手工单跑：`docker exec -w /app quantmind python -m
  backend.services.live_trading.services.call_auction_watch --once [--sample 09:25:05]`。
- **worker 拾新码**：`default_cluster().restart()`（8 分片全重启，~秒级）；
  改 `tdx_aidata/` 三件套后必做，否则 worker 侧 KNOWN_METHODS 旧版直接拒。
- **任务注册生效**：kill 8002 端口持有者 PID（看门狗 ~20s respawn）；
  日志出现 `[CallAuction] 任务启动 interval=5.0s ...` 即注册成功。
