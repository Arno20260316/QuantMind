## 1. A1 · 真单镜像券商无关

### 1.1 根因（实测）

| 事实 | 证据 ★ |
|---|---|
| `ENABLE_REAL_TRADING=true`、`REAL_BROKER_TYPE=tdx`、`broker:selected:CN=tdx` | 容器 env + Redis db2 |
| `real_trading_ready(redis,"CN") == (False, "broker_not_qmt_exec:tdx")` | `real_mirror_service` 实调 |
| REAL 直单能走通（`_get_broker` 按 `broker:selected:CN` 取券商） | `trading_engine.py:57/87/141-160` |
| `broker:selected:CN ∈ MARKET_BROKERS["CN"] = ["qmt_exec","tdx"]` | `broker_config.py:81` |

`real_mirror_service._real_trading_ready()`（993-1015）写死 `if selected != "qmt_exec"` →
在一个 TDX 部署上，镜像**永远** `skipped`，而同一账户的直单路径正常工作。这是
「装了但永不生效」的结构性空转，与 [[bridge-false-alive-account-channel]]、[[real-mirror-structural-noop]] 同族。

第二处硬绑：`_account_snapshot()`（658-687）直接 `get_qmt_exec_client()`，读 `can_use_volume`；
`_submit_payload` 只 `except QmtExecError` → 换成 TDX 后甚至账户查询都跑不起来（`account_unavailable:*`）。

### 1.2 修法

**① 能力判据单一源**（`backend/shared/real_positions.py` 新增）：

```python
def real_broker_capable(broker_type: str | None) -> bool:
    """该券商键能否承载持仓快照（= 能查真账户）→ 可作真单券商。

    复用 `snapshot_source_for_broker` 的既有映射（tdx*→tdx_bridge、qmt*→qmt_exec），
    该表与 `broker_config.MARKET_BROKERS["CN"]` 的互逆性由
    `test_account_source_to_broker_map_matches_broker_config_market_brokers` 锁定。
    """
    return snapshot_source_for_broker(broker_type) is not None
```

理由：`MARKET_BROKERS` 住在 `services/trade/routers/`（FastAPI 依赖），live_trading 不宜反向
import；而 `real_positions` 是**共享层**、已持有同一映射、且已有测试钉住两表互逆。
新增一份 list 常量 = 制造第三个漂移点，故不采用。

**② 就绪判据改写**（`real_mirror_service._real_trading_ready`）：

```python
if not selected:
    return False, "broker_unset"
if not real_broker_capable(selected):
    return False, f"broker_not_real_capable:{selected}"
return True, ""
```

保留 `real_trading_disabled`（env 关）不变；`selected` 解析顺序不变（Redis → `REAL_BROKER_TYPE`）。
**拒因字符串变更**：`broker_not_qmt_exec:{x}` → `broker_unset` / `broker_not_real_capable:{x}`。

**③ 账户闸门券商无关**（`_account_snapshot` + `_submit_payload`）：

```python
_ACCOUNT_CACHE_SECONDS = 10.0
_ACCOUNT_USER_ENV = "MIRROR_ACCOUNT_USER_ID"   # 真券商侧 user_id 被忽略（账户绑在桥/QMT）
_broker_cache: dict[str, Any] = {}

async def _account_snapshot(redis, force=False) -> dict:
    """真账户（资金 + 可用持仓），按**当前选定券商**取数，10s 缓存。

    出口统一：{"cash","total_asset","available_volume":{后缀式:数量},"broker"}。
    """
    # 缓存键含 broker_type：运维切券商后旧缓存必须失效
    broker_type = _selected_real_broker(redis)      # Redis → REAL_BROKER_TYPE
    ...
    broker = _get_real_broker(broker_type)          # create_broker cache，同 TradingEngine 先例
    account = await broker.query_account(
        resolve_db_account_user(_ACCOUNT_USER_ENV), tenant_id="default"
    )
    if not account:
        return {}                                    # 查不到 = 空（调用方 fail-closed）
    cash = account.get("available_cash", account.get("cash"))
    total = account.get("total_asset", account.get("balance"))
    available = {}
    for item in account.get("positions") or []:
        sym = StockCodeUtil.to_suffix(str(item.get("symbol") or item.get("stock_code") or ""))
        if sym:
            available[sym] = float(item.get("available_volume") or item.get("can_use_volume") or 0)
    return {"cash": float(cash or 0), "total_asset": float(total or 0),
            "available_volume": available, "broker": str(account.get("broker") or broker_type)}
```

调用侧（`_submit_payload`）：

```python
try:
    account = await _account_snapshot(redis)
except QmtExecError as exc:                    # 保留：QMT 侧仍可能抛
    return _skip(f"account_unavailable:{exc.code}")
except Exception as exc:                       # 券商构造失败（未知类型/配置缺失）
    return _skip(f"account_unavailable:{type(exc).__name__}")
if not account:
    return _skip("account_unavailable:empty")  # TDX 桥返回 {} —— 不许当「0 元」放行
```

字段口径对齐（★ 探针实测）：`TdxBroker.query_account` 返回 `available_cash/total_asset/positions[]`，
其持仓行键 = `stock_code / available_volume / total_volume / cost_price`（**无 `symbol`、无 `can_use_volume`**）；
`QmtExecBroker` 返回 `available_cash/total_asset`、持仓行含 `symbol` + `available_volume`。
归一式 `item.get("symbol") or item.get("stock_code")` + `available_volume or can_use_volume` 两者通吃。

实测样本：`cash=889592.23 total=918774.23`，4 只持仓 → 后缀式可用量
`{002074.SZ:100, 601000.SH:1700, 601857.SH:700, 603213.SH:700}` ★。

Broker 实例缓存：`create_broker` 每笔新建会每 10s 泄漏一个 `httpx.AsyncClient`
（`TdxBroker._client` 无 close）。按 `broker_type` 缓存实例，与 `TradingEngine._broker_cache`
同一先例；运行时改桥地址仍须 respawn（与既有行为一致，写入细案）。

## 2. A3 · 当日池进热集订阅

### 2.1 根因（实测）

- 热集候选源 = PG `engine_signal_scores` 最新 CN 交易日 `fusion_score` 降序 Top500
  （`hot_set_builder.py:143-170`）。
- 决策轮的池 = `data/reports/stock_picks/{YYYYMMDD}_picks.json`（`load_pool_doc`，`decision_round.py:334`）。
- ★ 实测：热集 562（`positions 152 [sim 98 + real 54] + candidates 500 + indexes 2 = 654`），
  池 `20261012` 30 行，**15 只不在热集**：
  `603357.SH 002884.SZ 000755.SZ 300453.SZ 603656.SH 000885.SZ 603277.SH 603299.SH
   002875.SZ 600817.SH 600308.SH 603309.SH 300789.SZ 002749.SZ 002282.SZ`。
- 后果：`l3.stale_quote`（`max_age_s=5.0`，fail-closed）——热集轮转 ~0.18s/只 × 562 ≈ **101s
  才轮到同一只票**，而池票若不在热集则**根本没有快照**（★ 探针：池内 30 只 `with_snapshot=0`，
  盘外）。

### 2.2 修法

**① 合成层新增 `pool` 组**（`backend/shared/hot_set.py`）：

```python
def compose_hot_set(*, positions, anomalies, candidates, pool=(), indexes=(), cap=DEFAULT_CAP):
    # 优先级：持仓 > 池 > 异动 > 候选（池票是「即将下单」的，截断不得先吃它）
    for group in (positions, pool, anomalies, candidates):
        ...
```

新增 kwargs 带默认值 → 既有调用点与三条纯函数测试（`total==6/kept==4`、`total==15/truncated==8`、
空源）**统计不变**（它们不传 `pool`）。

**② Builder 采集**（`hot_set_builder.py`）：

```python
POOL_SOURCE = "stock_picks/{day}"      # 仅用于报告展示

def _collect_pool(self, tenant_filter, day=None) -> tuple[list[str], str | None]:
    """当日候选池（决策轮同源 load_pool_doc）。池是全局产物，不随租户过滤。"""
    if not env_flag("QM_HOT_SET_POOL", default=True):
        return [], None
    from backend.shared.decision_context_source import load_pool_doc, now_cn
    day_str = day or now_cn().strftime("%Y%m%d")     # 池按**目标交易日**命名
    try:
        doc = load_pool_doc(day_str)
    except Exception as exc:
        return [], f"候选池采集失败: {exc}"
    if doc is None:                                   # 文件还没产出（北京 ~03:00/04:00）
        return [], None
    return [row.code for row in doc.rows if getattr(row, "code", "")], None
```

- 池文件**当日缺席不算错误**（凌晨未产出是常态）：`pool_file` 留空 + `pool=0` 进报告，
  每轮 60s 重读，文件出现即自动纳入（★ 时序：北京 03:00/04:00 周二~周六 产出）。
- 报告 `sources` 增 `pool` 与 `pool_file`；`:meta` 同步，运维可查。

**③ 分片压力可见**（`_shard_pressure`）：

`_shard_desired`/`hot_set_diff` 按**字典序**截断，不看 compose 的优先级 ——
即热集逼近 SDK 单订阅上限时，被截掉的可能是池票。这一点**无法靠排序消除**（分片在
订阅侧、优先级在合成侧），故如实**暴露余量**：

```python
def _shard_pressure(symbols, shard_count) -> dict:
    # crc32(symbol) % n 计数（与 collector.shard_symbols 同一算法）
    return {"shard_count": n, "shard_max": max(counts), "sdk_cap": SDK_SUBSCRIBE_MAX,
            "headroom": SDK_SUBSCRIBE_MAX - max(counts)}
```

`shard_max >= SDK_SUBSCRIBE_MAX` → **WARNING**「热集逼近 SDK 单订阅上限，请上调分片数」，
并写入报告/`:meta`。★ 实测并集 577 → 分片 `[85,90,79,65,80,91,87]`，**最大 91 ≤ 100，余量 9**。

**④ 端到端效果**：池票进热集后，两条既有链路自动覆盖它们——
`tdx_hot_set_feed`（桥轮询写标准键）与 `tdx_aidata` 订阅（写标准键），
从而使 `l3.stale_quote` 读到真实新鲜行情。**不改** `refresh_symbols_now` 兜底
（8336ed03 的现查现写仍保留：热集轮转 101s 对 5s 门仍是缺口，两者是互补而非替代）。

## 3. 交付与部署

### 3.1 A1 部署前必决策（真钱）

`mirror:enabled=1` + 白名单命中 + 非交易时段 → 队列 `mirror:queue` 会被写入，
**09:15 开盘由 drainer 补交**（[[mirror-rehearsal-mechanics]]「残留队列 = 活弹药」）。
故部署顺序二选一，**必须显式选**：

- **保守（推荐）**：部署前 `SET mirror:enabled 0`（或置 `mirror:kill=1`），改完代码 →
  热载 → 观察一轮 → 由用户决定何时开。这样「通道就绪」的翻转**不等于**「马上会下单」。
- **直接开**：保持 `mirror:enabled=1`，则部署当刻镜像即为活路径；开盘前须确认白名单与限额。

### 3.2 步骤

1. 细案（本文）→ 实现（A1 与 A3 分两个提交）→ `ruff check/format` + `npm run typecheck`；
2. 全量回归（`python backend/run_tests.py all`）→ **零新增失败**；
