# 桌面交易台死代码清理 修复细案（2026-10-14）

> 缘起：2026-09-17 commit `cbf663b8` 用 `PositionVisualBoard.ExecutionStrip` 顶替了交易台的
> 「今日执行」区块，但旧的卡片簇没有一起下线。此后 `DeskCards` / `DeskSections` / `deskModel`
> 里留下了一批**零生产引用的导出**；它们仍参与打包图，Rollup 只是因为没有活引用而 tree-shake 掉，
> 一旦有人重新 import 就会把过时的展示模型又接回来。本细案按用户拍板的**全量清理**口径收口。

## 一、侦查纪要（实证）

判断「死代码」不能只看导出是否被外部 import——**符号可以在定义模块内部被自己调用**。
`signalItemDrillEntries` 就是反例：它作为导出无人 import，但 `deskModel.ts:446` 由活的
`planOrderDrillEntries` 内部调用，所以它**是活的**，必须留。下表是按**全文件通读 + 全树 grep**
逐个确认的结论（不是 grep 一次的结果）。

### 1.3 `desk.pnl` 整块无人消费

本次不动后端（保留给未来的来源下钻，且改动面越小越好）。

## 四、边界

- **不改后端**：`desk.py` 继续投递 `pnl` / `execution` / `signals` 三块，前端少渲染不等于协议变更。

- 本轮只动前端展示层，**不涉及交易链路**，无真单/风控语义变更。
