# 因子排行榜 · 去重按钮细案（2026-10-15）

> 用户原话（2026-10-15）：「**因子排行增加一个去重选择按钮、 就是筛选那一样、
> 去掉重复的就行。然后重新排名**」
>
> 语义拆解：与筛选页**同一套去重口径**（相关 |ρ| ≥ 0.9 的同源因子只留一个）→
> 去重后的榜单**不显示**被剔因子 → 对保留因子**重新编号 rank 1..N**（综合分保持原值）。
>
> 流程：先侦查（§1，全部实测）→ 本文方案（§2–§3）→ 执行（§4 记录）。

---

## 1. 侦查事实（全部实测，非推测）

### 1.1 筛选页去重口径（须镜像的源头）

`backend/scripts/screen_factors.py` 的 `greedy_direct_corr`：

- **相关矩阵**：逐月末截面 Spearman = 每月末宽表按列 `rank(average, na_option=keep)`
  → pairwise-complete Pearson（`min_periods=50`）→ 82 期均值（`acc/cnt`，对角置 1）；
- **去重**：按强度序（`|ICIR|×1000 + |IC|`）降序贪心，逐个查已保留集合，命中
  `|ρ| ≥ 0.9` 即剔除，`duplicate_of` = 命中中 |ρ| 最大者；未覆盖的因子不参与（必保留）。

### 1.2 排行榜现状

`service.leaderboard(start, end, n, dataset)`：逐因子 KPI → `scorecard.composite_scores`
→ 按 `[insufficient, suspicious, composite, code]`（前两列升序=沉底，composite 降序）
排序 → `rank = 1..N` → 全列返回（前端本地排序/筛选）。私人库 4011 因子全量在榜。

### 1.3 为什么不能复用筛选页的 `cross_corr.npz`

筛选的缓存是**过门槛候选列口径（2520 列）**——门槛剔除的 1558 个因子（排行榜下半区
正是重复大户）不在其中。排行榜需要**全量 4011 因子**的成对相关，必须另建。

### 1.4 数据源与性能（spike 已实证）

- 数据源：`factor_research_private/monthly_scores.parquet`（7.6GB，457232 行 =
  **82 月 × 5576 股矩形** × 4011 因子列，float32 正态分位分）。宽表逐月一个 trade_date、
  行数恒定 → 行块边界规整；
- **4 次 matmul pairwise-complete Pearson**：`N=MᵀM, A=MᵀR0, B=MᵀR0², P=R0ᵀR0`；
  `num = N*P − A.T*A`；`den = sqrt((N*B.T − A.T*A.T) · (N*B − A*A))`；`C[N<50]=NaN`。
  与 pandas `rank().corr(min_periods=50)` 逐位对照：**max|diff| = 5.7e-15、
  |ρ|≥0.9 判定 0 不一致**（真实数据 300 列对照）；单期 rank 2.2s + matmul 3.2s
  + 代数 0.5s ≈ **5.9s** → 82 期 ≈ **8~10 分钟**（一次性离线）；
- 直接 pandas 逐对 nancorr 全宽 ≈ 250s/期 → 82 期 ≈ 5.7 小时（不可行）。
- 经典库：`factor_research/corr.parquet`（2701 行 = C(73,2)+73，列 `factor_a, factor_b,
  corr`，同口径逐月 Spearman 均值，其中 |ρ|≥0.9 共 84 对）→ 可直接建矩阵。

## 2. 方案

### 2.1 离线构建（新脚本）`backend/scripts/build_factor_panel_corr.py`

- 逐月流式处理（缓冲一行块）；每期 rank → 4-matmul → 累加 `acc/cnt`；
  均值落盘 `<quantdb>/factor_research_private/cross_corr.npz`：
  `matrix float32 (F,F)`（对角 1、未达 min_periods 的对为 NaN）、`names (F,)`、
  `used`（参与期数）、`generated_at` / 源文件审计字段；
- `--verify N`（默认 200）：随机抽 1 期 × N 列，与 pandas `rank().corr(min_periods=50)`
  金样对照（max|diff| 断言 + |ρ|≥0.9 判定一致性），**不通过拒绝落盘**（exit 1）；
- `--max-months` / `--out`：冒烟隔离；`--seed` 控制抽样。
- ⚠ 面板重建（`build_factor_panel_private.py`）后须重跑本脚本；排行榜按**覆盖回退**：
  矩阵里没有的因子不参与去重、必保留（不误剔）。

### 2.2 后端（4 处）

| 文件 | 改动 |
|---|---|
| `factor_research/dedup.py`（新） | `greedy_dedup(codes, names, matrix, threshold)` 纯函数（筛选器同语义：按给定序先到先得、`|ρ| ≥ t` 剔除、`duplicate_of`=最相关已保留者、未覆盖必保留；缓冲数组向量化判定）；`matrix_from_pairs(pairs_df)`（corr.parquet 长表 → (names, 矩阵)） |
| `factor_research/store.py` | `DedupMatrixMissing(RuntimeError)`；`dedup_corr(dataset)` → `(names, matrix) \| None`（classic←corr.parquet、private←cross_corr.npz，走 `_cached_obj`+mtime 失效） |
| `factor_research/service.py` | `leaderboard(..., dedup: float = 0.0)`：>0 时在 rank 赋值前做榜单序贪心去重（**保留榜单更靠前者**）→ 剔行 → **rank 重编号 1..N**（composite 不动）；`meta.dedup = {threshold, n_before, dropped, covered, applied}`；矩阵缺失 → `DedupMatrixMissing` |
| `factor_research/router.py` | `dedup: float = 0.0` Query 参数；`_run` 增捕 `DedupMatrixMissing` → **409** + 可操作文案（指对重建路径，不误导去点快照按钮） |

**语义决策**（与筛选页的差异，均为口径内）：筛选页留「强度最高」者，排行榜留
「榜单最靠前」者（综合分序）——同一种「保留代表」精神，判据各自随页；相关阈值与
聚类口径逐字同源（逐月截面 Spearman 均值、|ρ| ≥ 0.9、直接贪心非传递闭包）。
