# 通达信桥数据面全量接入 实施细案（2026-10-15）

> 状态：**批次 0（实桥探针）完成** → 批次 1 骨架施工中。
> 决策基线（用户已定）：① 前端「通达信桥」面板**随本批交付**（挂批次 2）；② 历史回填存储 = **PG 近 5 年 + 全历史 parquet 归档**。
> 探针脚本：`backend/scripts/tdx_ingest_probe.py`；证据样本 85 份 / 2.6MB 归档 `data/tdx_bridge/_probe/`（`data/` 为符号链接，不入 git）。

## 1. 背景与目标

用户要求「扩出来、只要能提供的数据都需要」。Windows 通达信桥（`tools/bridge-windows/`，HTTP :8550）经 `/api/v1/tdx/call` 以**动态白名单**（`routes.py:451` = `TdxClient` 全部公开方法）暴露 tqcenter 数据面。平台当前只消费了热集快照与 L2 的 `get_exday_data`/`get_more_info` 极小一部分。

本批目标：把桥可提供的数据面以「日增量全自动 + 历史回填 + PG 落库 + parquet 归档 + 状态可见 + 查询 API + 管理面板」接入，**零桥侧改动**（探针已证实无必要），严格遵守桥 600 req/min 共享配额。

### 2.2 成功但**数据无效**：zdt（待权限/缓存解锁）

`get_zdt_data` 返回 15 字段结构体但全零。**证伪「恰好无涨停」**：与东财涨停池（2026-10-15 共 34 只）交叉，样本内 9 只当真涨停股全部 `ZDTStatusNow=0`。

官方前置（已核）：① 客户端需**短线宝权限**（普及增强版/财富版/专业版）；② 「首次调用客户端需要缓存数据，首次可能为空」。

处理：探针留档；**明日盘中（10-16 上午）复测一次**；解锁前 zdt 档位挂起、**不入库**（全零入库=污染）。

### 2.3 被客户端数据包锁定（红）：GP/BK/SC/GO/FN 家族

24 个用例（GP01–GP36 / SC / BK5-17 / GO / FN1-107、range 与 by_date 两式、批量 1/2/50）**全部** `ErrorId=10: json has no table_list:{...}`，快失败 ~2s。

- **已证伪假设**：`refresh_cache('AG')` 不能解锁——返回 `Refresh Cache Success.` 后五个家族重试仍 table_list（refresh_cache 仅刷新行情缓存，`client.py:331`）。
- **根因**（官方文档 ×34 处前置条件交叉印证）：需先在 Windows 通达信客户端「**系统 → 盘后数据下载**」下载 **股票数据包**（GP/BK/SC 系）与 **专业财务数据/财务数据包**（FN 系）。属环境侧前置，非协议问题。
- **就绪判据**：数据包下载后重跑 `python3 backend/scripts/tdx_ingest_probe.py --all` 即答复：返回形态、批量上限、最早可及日期、FN 分页语义。
- **命名字段两版已入探针**（`gp_value_np`/`gp_by_date_np`/`sc_np`/`sc_by_date_np` = 非补零 `GP1`/`SC1`；原用例 = 补零 `GP01`/`SC01`），一次重跑同时判明哪种被服务端接受。

### 2.4 桥行为怪癖（设计必须消化）

1. **tqcenter 串行队列**：单次大调用会按停全桥——zdt 2000 超时后紧邻的 pricevol（此前 3s 成功）连续 30s+ 超时 ~90s。⇒ 批量按 **500** 保守设计（zdt 档 12 批），单调用读超时 **60s**，盘后窗内严格顺序执行。
2. **86400s 内存缓存**：`get_more_info/get_stock_info/get_financial_data` 86400s、`get_stock_list/get_sector_list` 3600s。缓存键=原始 params JSON，在参数过滤**之前**建键（`client.py:177-190`）⇒ 加签名外参数 `_nc`（如时间戳）即绕缓存且不改变实际调用（已读码验证）。
3. **失败信封**：桥 `success:false` → 既有客户端 `tdx_push_service` 折叠为 `{"result": None}`，无法区分失败。本采集器**必须把 None 当失败**（不复用 10s/无校验口径）。
4. **配额**：600 req/min/IP 全端点共享；盘中热集 ~333 + L2 ~300 已占满。⇒ **采集只落盘后窗口**，预算默认 **180/min** 令牌桶。

## 3. 总体设计（相对批准方案的探针修正）

模块布局、采集纪律、存储口径、暴露面与批准方案一致，本档只记**探针修正点**与**档位终表**。

### 3.1 探针修正点

1. **pricevol 前移进批次 1**：全市场一次调用即得收盘快照 → 新增 `tdx_pricevol_daily` 表（PK stock_code+trade_date；列 last_close/now/zaf/volume_hand），挂 15:31 档（原批次 3「补遗」取消）。
2. **zdt 挂起**：骨架保留 parser/sink（形态已确认）与档位占位，但数据无效期间不执行、不入库；解锁判据 = 盘中复测非零。
3. **GP 家族「照挂等包」**：档位照常挂，遇 `table_list` 错误时数据集状态置 `blocked`（不重试、不告警刷屏，按日一次提示）；数据包就位后**零改动自动转正常**。parser 先按官方文档形态实现。
4. **divid/gb 改轮转**：divid 一次即全史（5581 调用=31min 不值当），gb 需逐股显式日期 → 两者合并日轮转（每日 1000 只，5.6 天一环，游标在 `tdx_ingest_cursor`）；新股/新债优先插队。
5. **kzz / trackzs 宇宙**：`market=32`（331 CB）/ `market=91`（445 指数），日全刷（≈2 + 2.5min）。
6. **more_info 预算实测**：5581 单股调用 @180/min ≈ 31min → 16:45 档（17:16 完），下一个档 17:20 后续重排见 3.3。
