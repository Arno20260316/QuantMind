# 因子研究 · 左侧目录「自动分类 + 中文名」细案

> 需求原话（2026-10-15）：「因子研究的左侧、只有大文件夹、后面全是一堆因子英文、
> 能在增加一个因子的分类吗、比如量价、财务、做自动分类可以吗」
>
> 流程：先侦查（本文 §1–§3）→ 本文方案（§4–§5）→ **用户审** → 再动手。

---

## 1. 侦查事实（全部实测，非推测）

### 1.1 现状：左栏为什么像「一堆英文」

- 左栏（`CatalogSidebar.tsx`，248px）树模式两级：**大文件夹（l1）→ 分组（l2）→ 因子行**。
- 实测 `factors.json`（4011 因子 / 13 个大文件夹）：**每库的 l2 有且仅有 1 个取值，且就等于库自身**
  （如 Alpha 因子库 429 个因子的 l2 全是 `alpha_library`）。即第二级**零信息量**——
  点开大文件夹后看到的就是一列平铺因子。
- 因子行主标题用 `name_cn`，而私人库构建脚本落的是 `name_cn = name`（**代码本身**）：
  于是满屏 `gtja_042`、`f13_0001`、`feat_absdiff_ac_diff`。这就是「一堆因子英文」的来源。

### 1.2 三个现成的权威中文词表（都在本地，零外部依赖）

| 来源 | 覆盖面 | 内容 | 实测命中 |
|------|--------|------|----------|
| `data/factor1300/name_map.json` | 1252 条 | **中文名 + 23 个中文类**（估值因子/技术因子/…） | 目录内 **f13_ 831/831、Alpha101_ 101/101、Alpha191_ 191/191 全命中** |
| `data/factor_defs/formulas.json` | 2603 条 | 每条一个**中文类**（10 类）+ 中文 desc | 目录内 feat_ 前缀 **1287/1287 全命中**（其中 610 条源词表自身就标「其他/未分类」） |
| `quantdb_factor_dictionary.py`（代码内前缀表） | L1/L2/每日特征 | 前缀 → 中文类（如 `mom_`→动量、`micro_`→价差与微观结构） | L1/L2 前缀族全命中 |

即：**1123 个因子（f13 + Alpha101_ + Alpha191_）连中文名都现成有**（`f13_0001` = 市盈率TTM、
`Alpha101_001` = Alpha101_1），只是构建脚本没接。

### 1.3 其余库靠确定性规则即可覆盖

Alpha101/GTJA191/Alpha158/Alpha360/聚宽 JQ110/通达信 TDXGS 代码本身自证（经典量价/技术指标库）；
`lu_/ld_`=涨停/跌停结构、`mg_/sl_`=两融、`NEWS_`=新闻情绪、`CONCEPT_`=概念、`micro_`=微观、
`HD_`=持仓结构、`FIN_`=财务、`IND_/style_/beta_/规模市值`=风格行业——全部可枚举规则收口。

## 2. 自动分类的实现口径（**零 AI 推断**）

优先级链（命中即止，全程确定性映射、可单测）：

1. **手工表**（每日特征 44 例逐码表、66 个散码）——小集合，穷举锁死；
2. **词表 A**：`name_map.json` 中文类 → 统一类（23→8 映射表）；
3. **词表 B**：`formulas.json` 中文类 → 统一类（10→8 映射表）；
4. **前缀规则表**（§1.3，正则有序表）;
5. **挖掘因子关键词表**（`rd_*` 等英文透明词根：amihud→流动性、momentum→动量…）；
6. **兜底「其他/未分类」**——如实展示、可计数、可审计，**不硬猜**。
   源词表已标「未分类」的（610 条）**不覆盖**：上游明确说了没分类，规则去猜反而是造假。

词表文件缺失（数据目录没挂）→ 相应层级跳过 + warning 日志，catalog 照常出（绝不 500）。

## 2.5 用户决策（2026-10-15 确认）

- **树结构**：**库 → 类别 → 因子**（保留大文件夹作顶层，冗余 l2 层替换为语义类别）✓
- **类别体系**：**12 类细划分**（量价三分、基本面三分），另设「其他/未分类」兜底桶 ✓

## 4. 改动方案

### 4.1 后端（读取时富化，不动产物、不重建）

- **新增** `backend/services/engine/factor_research/taxonomy.py`：唯一实现。
  对外 API：`classify_code(code) -> category_id`、`category_for(code) -> Category`、
  `chinese_name(code) -> str|None`、`enrich(entry) -> 新 dict`（加 `category`/`category_name`，
  仅在原 `name_cn` 为空或等于 code 时回填中文名）；词表 mtime 缓存；
  缺失/损坏降级为 other + 告警，绝不抛；附**全量金样测试**（优先级链 + 分布回归 + 降级用例）。
- `service.catalog()` private 分支：每个 factor 富化 `category`（id）与 `category_name`（中文）；
  `name_map` 有中文名的 1123 条顺带补 `name_cn` 为中文（**只补空/等于代码的，不覆盖已有真名**）。
- 词表定位：`resolve_quantdb_dir().parent / {factor1300,factor_defs}`（与现有 `quantdb_paths` 同规）。

### 4.2 前端

- `CatalogSidebar.tsx` 树模式：第二级从**冗余的 l2** 换成**类别**（大文件夹 → 类别 → 因子）。
  l2 层既然 100% 零信息，替换无任何损失；类别行使可折叠 + 计数徽标（`动量技术 635`）。
- 类别行点击 → 排行榜过滤：`CategoryFilter` 增加可选 `category` 字段；
  `leaderboardFilters.ts` 的匹配多加一个条件（现有 l1/l2 语义不动）。
- 平铺模式行内路径 `L1 / amt` 改为 `库 / 类别`。
- 类型 `FactorMeta` 增 `category/category_name`（可选字段，缺省兼容）。

### 4.3 不做的事（边界）

- 不改 `build_factor_panel_private.py`、不重跑快照（读取时富化，新因子自动进类）；
- 不引入 LLM/embedding 猜分类；不动 classic 数据集（它自带中文目录）；
- 前端不动布局宽度/折叠记忆等既有行为。

## 5. 验收

- 后端：`taxonomy` 单测（金样映射、优先级链、降级、分布回归）全绿；catalog 接口实测富化字段；
- 前端：vitest（过滤纯函数新分支）+ `npm run typecheck`；
- 实机：部署后浏览器验证左栏 库→类别→因子 三级树、类别点选联动排行榜、中文名显示。

## 6. 工作量

后端 1 新模块 + service 小改 + 单测 ≈ 2h；前端 2 文件 + 测试 ≈ 1.5h；实机验收 0.5h。合计约半天。
