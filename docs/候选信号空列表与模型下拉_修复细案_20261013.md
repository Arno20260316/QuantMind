# 「候选信号」空列表 + 模型下拉不全 修复细案（2026-10-13）

> 缘起：用户报「实盘交易 候选信号都没了呢、候选信号里面的模型只有几款，没有显示全啊。」
> 两个现象**根因不同**：一个是**读侧键格式错配**（真 bug，必须先修），
> 一个是**上游推理覆盖率**（不是下拉框的 bug，但要有可见性，否则用户永远以为界面坏了）。

## 一、侦查纪要（实证）

### 数据实况（`docker exec quantmind-db psql`，2026-10-13 实测）

| 观测 | 值 |
|------|-----|
| 各日 `engine_signal_scores` 归一化后的 distinct 标的数 | 10-13 → **3835**；10-12 → 6580；10-09 → 6530 |
| 10-13 当日行形状 | **prefix 3274 行（全部有 `signal_side`）+ suffix 562 行（`signal_side` 全 NULL）**，**无 bare 行** |
| 10-13 当日来源 | prefix 3274 来自 **batch** 推理（`mdl_cust_train_20261008135709_…`）；suffix 562 来自 **realtime** |
| 10-12 当日行形状 | bare 9742 + prefix 6480 + suffix 612（**三种并存**） |
| 后端 `model_options` SQL 原样复刻的行数 | **12** |
| `qm_user_models` 状态分布 | ready **91** / archived **23** / candidate 1 |
| `qm_model_inference_runs` distinct `model_id` | **22** |
| ready 且**曾有**信号的模型 | **11** |
| ready 且**近 30 天有**信号的模型 | **6** |

> 注意：`_MIN_SIGNAL_COVERAGE = 1000` 的覆盖率闸门在 10-13 **是通过的**（3835 ≥ 1000），
> 所以当日**没有**回退到「最近的任意 trade_date」。空列表与此无关。

### 现象 (a)：候选信号列表为空 —— 键格式错配

`backend/services/api/routers/stock_terminal.py` 的 `/stock-terminal/list`：

1. 打分行读出来时**按字面 `symbol` 建键**，并且写了一句事实错误的注释：
   ```
   sym = str(r[0])
   # engine_signal_scores.symbol 为纯数字 600519（不带市场后缀）   <-- 与实况相反
   sfx = sym if "." in sym else sym                                  # <-- 恒等，空操作
   score_info[sfx] = {...}
   ```
   10-13 的行是 **prefix（`SH600000`）**，于是 `score_info` 的键是 prefix。

2. 三个消费点却**统一用 bare 码**取值：
   - `stock_terminal.py:2078-2089`：`df["_code"] = df["Symbol"].str.split(".").str[0]`，再 `score_info.get(c)`
   - `stock_terminal.py:2296`（`_item()`）：`score_info.get(str(r.get("Symbol")).split(".")[0])`
   - `stock_terminal.py:2324`（趋势）：`trend_map.get(str(r.get("Symbol")).split(".")[0])`

   而 parquet 宇宙的 `Symbol` 是 **suffix（`600519.SH`）** → `.split(".")[0]` = bare `600519`。
   prefix 键 ↔ bare 查询 → **全 miss** → `_fusion`/`_side` 全 None。

3. 前端 `SignalsExplorerPage.tsx:66` 默认 `filters = { side: 'BUY' }` →
   `if side: df = df[df["_side"] == side]` → **空集**。所以：**无论选不选模型都是空**。

同类错配还有 `_trend_map()`（`stock_terminal.py:1478`）——它也是「键=字面 symbol、查=bare」。

**为什么现有实现是对的却没用上**：`backend/shared/signal_scores.py` 里**已经有**唯一正确的
归一化实现（`normalize_a_share_symbol` / `build_score_map`），其 docstring 甚至写明
「与候选信号页 `/stock-terminal/list` 同源」——**这句话是假的**，`/list` 从没调用过它
（只 `import score_freq_of`），而是手搓了 `.split(".")[0]`。

### 现象 (b)：模型下拉只有几款 —— 数据如此，不是下拉坏了

- 下拉选项由 `model_options` 单独查询生成，**实测就是 12 行**（`LIMIT 200` 未触顶）：
  9 个用户模型 + 3 个 NULL 状态的系统模型（`sys-model_qlib_qdb` 等）。
- 但库里 **91 个 ready** 模型、**22** 个有推理 run，却只有 **11** 个**曾经**产出过信号、
  **6** 个近 30 天有信号。**真正的缺口在上游推理覆盖率**（当日批量推理失败的连锁后果，
  见 `docs/实盘TDX桥探针_信号链_时间口径_修复细案_20261013.md` 侦查 #3）。
- 叠在数据之上还有**两处代码机制**放大观感：
  1. **带 `model` 参数的请求返回 `models: []`**：`model_options` 的取值只有
     `if not model and 缓存有效: … elif not model: …`——任何带了模型的请求（含前端
     用户选完模型后的刷新）都不回选项，前端就看起来「越筛越少」。
  2. `StockSidebar.tsx`：`const models = resp.models ?? []; if (models.length) onModels?.(models);`
     ——**只在非空时覆盖**，选项列表**永不清空、也不随 `filters.model` 变化重建**。

**结论**：(a) 是必须修的真 bug，且**不止一条根因**（键形错配 + 市场口径漏 `CUSTOM`
+ 去重键未折前缀，见 A/A2）；(b) 不是下拉 bug，修 **代码机制 1/2**（让选项恒有、
且带模型的请求也回选项）+ 让上游覆盖率**可见**，才是对症的。

## 二、改动清单

### A. 后端：`/stock-terminal/list` 打分键统一为 bare 码（修 (a)）

- `backend/services/api/routers/stock_terminal.py`
  - 新增模块级私有助手 `_bare_symbol(raw) -> str | None`：接受 **prefix / suffix / bare**
    三种写法，统一折叠成 **bare 六位码**（A 股），非 A 股返回 `None`。
    **复用 `backend/shared/signal_scores.py::normalize_a_share_symbol`**（它已处理
    prefix/suffix/bare），外层只做「prefix → 去前缀」的最后一步折叠；
    不再手搓 `.split(".")[0]`。
  - 打分行入库时改用 `_bare_symbol(str(r[0]))` 作键（替换 `sfx = sym if "." in sym else sym`），
    **并删除事实错误的注释**（「symbol 为纯数字 600519」）。
  - `_trend_map()` 的 `out[sym]` 同样改用 `_bare_symbol(sym)` 作键（保持与消费端一致）。
  - 三个消费点**保持不变**（它们本来就是 bare 口径，现在键也对齐了）。
  - 打分 SQL 的市场口径统一走 `signal_scores.py::A_SHARE_MARKET_SQL`
    （`(market IS NULL OR market IN ('CN','CUSTOM'))`）。
    **本项是空列表的第二条直接根因，不是「口径卫生」**（初稿判断错了，实跑证伪）：
    详见下方「A2」。

### A2. 后端：市场口径 + 去重键（空列表的**两条**直接根因，初稿均判错）

#### A2-1 市场口径漏掉 `CUSTOM`（直接根因之一）

- 初稿在打分 SQL 上补的谓词写作 `(market IS NULL OR market = 'CN')`，并自评
  「口径卫生，非本 bug 直接原因」。**实跑证伪**：`engine_signal_scores.market` 只有
  两个落库值——`'CN'`（14,407,245 行，2024-08-02 起）与 `'CUSTOM'`（13,227 行，
  2026-10-09 起）；而 2026-10-13 **全市场带 `signal_side`（BUY/SELL）的行只存在于
  `CUSTOM` 桶**（当日 `cn_side=0`、`cust_side=1310`）。按 `'CN'` 单值过滤 → 当日
  一条 BUY 都不剩 → 默认 `side='BUY'` 命中空集。**不是卫生项，是列表为空的直接原因。**
- `'CUSTOM'` 是**一等公民市场**，不是脏数据：
  `quantdb_factor_reader.MARKET_FACTOR_SOURCES` 收录（`CUSTOM: (l1_factors,)`）、
  `normalize_market` 放行、`model_recipe._FACTOR_MARKET_ALLOWED` 收录、
  前端 `ModelHubPage` 有「自定义市场」选项、`getMarketConfig('CUSTOM')` =
  `a_share + SSE + SH000300`（按设计就是 A 股形态）。落库 symbol 13227/13227 行
  **全是 prefix 形 A 股代码**，`feature_version = script_v1_<model_id>`。
- 落地形态：抽成 `signal_scores.py::A_SHARE_MARKET_SQL =
  "(market IS NULL OR market IN ('CN','CUSTOM'))"`，三条 SQL 模板 + `stock_terminal`
  的打分 SQL **共用同一常量**（不再各写各的 `CN` 字面量）。

#### A2-2 去重键未折到裸六位（潜伏的第二条缺陷）

- `SQL_SCORES_BY_DATE` 原文是 `SELECT DISTINCT ON (symbol) … ORDER BY symbol,
  created_at DESC, id DESC`，Python 侧 `build_score_map` 又是「后写覆盖」——两者叠加
  **等价于按字面序挑行**：前缀形（`SH600036`）字面排序恒在纯数字之后 → **恒胜**，
  与 `created_at` 最新无关；同一裸码的多形态行因此**根本无法合并**。
- 实测（2026-10-09，生产口径复刻）：**3235 个裸码**取到了错的分数/方向行；
  该日按折叠键出 `side=1304`，按字面去重出 `side=1341`。
- 落地形态：新增 `signal_scores.py::SYMBOL_FOLD_KEY`（在 `SYMBOL_COUNT_KEY` 之上再折
  前缀形），**覆盖计数与打分去重共用一个归一键**；`stock_terminal._trend_map` 的键
  也改用 `_bare_symbol`，与消费端对齐。
- 修后断言：重复行里「字面更后但 `created_at` 更旧」的那条**不得**胜出
  （见 `test_stock_terminal_symbol_keys.py::_STALE_DUP`，旧实现下这里会取到 0.99）。

### B. 后端：模型选项恒回传 + 带 model 的请求也回（修 (b) 代码机制 1）

- `backend/services/api/routers/stock_terminal.py`
  - 把 `model_options` 的取值从「只在 `not model` 时算」改为**无条件计算**（缓存键不变），
    使**任何** `/list` 请求都带 `models`；
  - 保留缓存（`_model_options_cache` + `_UNIVERSE_TTL`），不改查询语义、不改 90 天窗口口径；
  - 选项排序首位恒为当前默认模型（`is_default` 优先），与现行为一致。

### C. 后端：模型清单补「有信号」标记与查询窗口说明（修 (b) 可见性）

- `backend/services/api/routers/stock_terminal.py`
  - `model_options[i]` 增加 `has_signals_30d: bool`（是否近 30 天有打分行），
    上游覆盖率事实**直达下拉框**——用户能看出「这款没信号」而不是「界面漏了」；
  - **不改** `LIMIT 200`、不改 90 天窗口（改窗口会改变候选集合语义，另议）。

### D. 前端：模型选项不再「只增不减」（修 (b) 代码机制 2）

- `electron/src/features/stock-terminal/components/StockSidebar.tsx`
  - `if (models.length) onModels?.(models)` 改成**无条件 `onModels?.(models)`**，
    空响应也能如实清空（不再留着上一次的陈旧列表）；
  - 响应里 `models` 缺失（老后端）时**不覆盖**，保持向后兼容。
- `electron/src/features/stock-terminal/components/StockFilterPanel.tsx`
  - 下拉选项在 `has_signals_30d === false` 的模型后加**弱化后缀**（如「· 近 30 天无信号」），
    仅文案，不影响可选性。

### E. 前端：空列表要给「为什么空」而不是「什么都没有」（体验兜底）

- `electron/src/features/stock-terminal/components/StockSidebar.tsx`
  / `electron/src/pages/trading/tabs/SignalsExplorerPage.tsx`
  - 列表为空时，行数区展示**如实空态**：区分「当日无信号日」/「该模型当日无信号」/
    「筛选条件命中 0」三种，各给下一步（如「换模型」「放宽位置筛选」「去系统健康看推理失败」）。
    文案**只描述事实**，不臆测。

## 四、不做 / 待议

- **不改** `model_options` 的 90 天窗口与 `LIMIT 200`：改了会动候选集合语义，另案评估。
- **不在本细案**修上游推理覆盖率（当日批量推理全 failed 的根因属
  `实盘TDX桥探针_信号链_时间口径_修复细案` 侦查 #3 范围，改动 D 只把事实**显性化**）。
- `SYMBOL_COUNT_KEY`（覆盖计数）与打分去重**原先各用各的归一键**：初稿判「属卫生项，
  本细案不动」，**但实修时统一了**——新增 `SYMBOL_FOLD_KEY` 在 `SYMBOL_COUNT_KEY`
  之上再折前缀形，覆盖计数仍用 `SYMBOL_COUNT_KEY`（A2-2 的 3235 行错分正是因为去重键
  没折前缀）。两键的**折叠强度差异是刻意的**：覆盖计数只关心「算几只」，
  去重还要挑出正确的那一行。
- **遗留（未决）**：`HoldingAlertSettings.test.tsx` 存量 vitest 失败
  （断言 `分数阈值` vs 实际渲染 `分数预警线`），与本细案无关，尚未处理。
