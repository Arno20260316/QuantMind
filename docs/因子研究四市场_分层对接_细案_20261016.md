## 一、结论先行

**一句话**：因子研究两条链路（研究工作台 `factor_research` 14 端点 + 因子报告 `factor_report` 9 端点）现为 100% A 股口径——路径解析、数据集注册表、基准表、构建脚本、前端文案全链 CN。四市场分层 = 后端按 `market` 参数化两条链路（三个路径收口点 + 两个注册表 + 四个构建脚本）+ 前端接入全局市场选择器 + 非 CN 诚实面。**CN 行为与存量产物零改动**（market 默认 `"CN"`、数据根=市场、无目录迁移、存量测试不动）。

**可行性已实测判定**（决定设计边界，详见 §2.4）：

1. 报告链路 `close_fwd` 标签**只从分区目录名取日期**、全程不读任何日期字段 → HK/US/FUTURES `l1_factors`（无日期列、自带 OHLCV+close）可直接构建；无 OHLCV 的 donor 机制现成（HK ccass/south → 同市场 l1）。
2. 基准面：HK/US 的 `index_daily` 已在盘上且 schema 与 CN 同构（HSI.HK / SPX.US），只差 per-market 根；FUTURES 无任何指数数据 → 走现成 `available:false+reason` 降级（绝不造 0）。等权基准在 factor_report 链路无实现（只在 factor_backtest），不在本期。
3. 工作台私有面板：因子值与 fwd_ret（各市场 daily_forward 现算）可行；硬缺口=instrument（ST/退市）、行业、valuation、FUTURES 基准 → 对应字段诚实 '—'；universe 按市场重定义为全池近似（该市场无 ST/退市口径）。
4. 原始列陷阱：HK/US/FUT `l1_factors` 混有约 10 个非因子原始列（adj_factor/turnover_rate/pe_ttm/pb/roe/bp/ep_ttm/float_mv/total_mv/ln_mv_total）——两侧 meta/DROP 列清单必须按市场剔除，否则原始列混入因子轴。
5. FUTURES 数据极稀疏（最新分区 2 行、中段抽样 ~18 行、单日最多百余行）——期货侧横截面统计弱是**数据实况**，UI 如实呈现不掩饰。

**交付形态**（对齐推理中心/模型管理前作机制）：单页读取全局市场（市场切换即整页换数据），非 CN 可用面 = 私有因子库工作台 + 因子报告 + 本市场指数基准；诚实阻断面 = classic 经典库（A 股专属）、联合筛选七库（CN 口径产物）、毕业桥（CN 管道）、FUTURES 基准/估值/行业。HK/US/FUTURES 快照为零 → 交付含**本轮实建三市场快照**（构建脚本与生产路径一致，UI 一键构建同 CSP；运维面无需用户另拍动作）。

### 2.4 可行性判定（构建路径实测——设计边界的直接依据）

**报告链路（factor_report）**

## 三、差距清单与设计

### 3.1 设计总原则（维护性优先）

1. **一个市场参数走天下**：两条链路所有端点加 `market`（默认 `"CN"`，存量调用与测试零破坏）；解析唯一收口 `normalize_market()` + `market_data_dir()`。**非法 market 必须 4xx 拒绝，绝不静默落 CN**。
2. **数据根=市场，树形同构**：`<market_root>/6_ml_datasets/<lib>`、`<market_root>/factor_research{,_private}`、快照 `report/` 全沿现目录习惯——CN 存量零迁移，加市场零新机制。
3. **注册表按市场声明**（不是 if-else 散落）：报告侧 `DATASETS_BY_MARKET`、工作表侧市场可用性表、每市场 meta_cols/基准表。**加一个市场 = 加一个注册表条目**，不动逻辑代码。
4. **诚实面三铁律**：能算才显示；缺失一律 '—'；不可用面给 reason + 指引，绝不造数、绝不回退其它市场数据。
5. **前端清单单源**：数据集胶囊/基准选项/默认基准从后端响应取；TS 只保留展示标签。
